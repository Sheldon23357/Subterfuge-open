# 指令执行、回执与恢复

## 单一执行链

所有 bot 模式返回同一指令信封，由控制器解析参数、核对身份与功能范围、验证当前观察/资源/控制权，再执行。策略模式没有直接提交远程命令的通道。预测结果、候选评分和本地哈希不能授予写权限。

模型发送前按当前观察、消息、重要事件、指挥官版本和私有状态依据重新准入；未发送的过期票据重新构建，不伪记为已完成调用。已返回的模型回复不因状态版本或后续任务变化整体拒收，而按当前权限和实际冲突原子发布；该接收策略不放宽游戏命令提交时的资源、权限、人工保护和版本检查。发送边界审计只证明交给 provider 适配器，不能证明远端已接受。

## 接受、执行与实际结果

分层协同操作将命令拒绝与运输结算分开：`failed` 表示明确拒绝或失去控制；`ended` 表示已有实际结算证据的运输结束，例如战斗结束未交付或回收；返航与取消出航记为 `cancelled`。只有实际交付证据才能完成指定运输任务。子命令保留结算类型与事件身份，运输结束会释放承诺并触发目标复查，不记作接口调用失败，也不伪装成功交付。没有实际结算证据时保持待核对，不能凭舰队消失结束操作。

- 客户端先持久保存 intent 和幂等键，再提交服务器。
- accepted 表示服务器已记录，不能说游戏效果已经生效。
- 持久最终回执证明相应效果提交或明确拒绝；实际抵达、战斗和资源变化还需授权事实。
- 超时、断流、损坏响应和存储错误可能留下 unknown，必须查原 key。
- `/commands/lookup` 的 found、权威保留范围内 absence 与 history_unavailable 含义不同；未知或无覆盖不能当作没执行。
- 不修改原 intent 的版本、fence 或 key 来重发。重连、失租、暂停和换局均不能清空旧账本。

实际执行回执与事实观察游标先按原事务保存，再由模式的确定性 `onReceipt` 回调更新本地协议投影；回调只接收当前回执身份及本地账本查询，不提供模型、搜索或远程提交能力。只更新与本次回执身份匹配的原始尝试，不因无关回执将正在发送的命令误记为未执行；崩溃后仍由持久账本恢复。撤军确认等待完整批次回执，部分成功和未知结果不能解锁签约。

SDK 与 SQLite 适配器维护未决 outbox。判断未决项需读取完整存储适配器，不能只看分离存储核心中的空 outbox 字段。

协商后的服务器批次沿用同一执行链和整批约束校验，保留每个子项的原始依据与独立幂等键。服务器在一次串行结算中核对原始依据并逐项检查当前合法性、资源、人工优先级和控制权限，失败后停止后缀；已提交前缀、明确拒绝和未执行分别记录。父请求和子项均有权威账本回执，丢失响应后查询原身份，不将整批作为新请求重发。最终授权快照交付失败时保留已确认的子项结果，等待观察恢复。详见[公开协议](../../protocol/player/v2/README.md#leases-and-durable-commands)。

## 版本与本地提交

游戏操作校验 revision、会话、租约 fence、授权和确认指令版本。已有回执等待确认时禁止新增游戏写入；租约续约和读查账仍按安全条件进行。

私有状态先读取一致的决策视图，提交时按对应领域依据和本地事务规则校验。战略省略字段保留当前值，不能用陈旧审计负载覆盖外部更新。finish 原子提交笔记、战略、提醒及允许的确认清理，只核对本地指挥官版本和 CAS，不另行远端读取身份、控制权或完整观察。尚未收取的远端变化在后续正常观察中处理，保存私有计划不代表其已通过下一次行动的权限校验；实际游戏操作仍核对当前权限，不能回滚已接受的远程操作。

观察轮询耗时作为程序审计独立保存，保留持久笔记和已确认指挥官状态，不复用或刷新在途决策的旧提交依据。观察期间出现新的人工事实时，审计仍可落盘，旧模型结果继续按原依据拒绝或延后处理。

批量最多八项，顺序执行；失败或 unknown 后停止，已接受项不回滚，剩余项标未执行。相同来源和目标的待发舰可能是编辑而非新增，不能简单相加兵力。

## 控制权

启动核对当前租约，不自动 takeover。其他短租约可在有界只读等待中观察；另一方续租、长期租约或结果不明则明确停止。暂停取消等待，不释放别人的租约。

瞬时 owned=false 可能出现在回执屏障期间，应结合服务端当前会话、generation 和未过期租约判断。未确认续约、过期或权限撤销时不能写入。重启保持暂停，由操作者恢复明确运行意图。

## 自动恢复

本地 CAS 发现指挥官要求、战略或私有资料已更新时，丢弃旧计算及未提交修改，保留启用状态和未完成触发原因，不在本轮重新计算。后续正常轮次读取新依据并先核对既有回执；同 tick 的单轮准入仍有效，允许回合正常就绪推进，已接受操作不重复发送。

可恢复模型故障前两次分别等待 15、30 秒，之后按 60、120、240 秒递增，最高 300 秒。只读网络临时故障有界退避；明确认证、配置、身份不匹配和结构错误不作为普通抖动重试。具体分类与限额以 `controller/runtime/recovery.ts`、`contracts/provider-error.ts` 为准。

游戏操作已有确定提交回执、但后续局势读取失败时，保留席位运行意图和可续约租约，按 15、30 秒递增至最高 300 秒自动重试读取，不永久停席。期间禁止新增游戏写入和就绪上报；授权观察恢复后先核对未决账本，再继续整轮，已接受操作不重发。保留原始读取异常诊断，不能将读取失败改写成操作失败或未执行。

运行层启动、续租和就绪上报遇到临时网络中断或临时服务错误时，同样保留启用意图并退避自动重连；重连先查原协议账本再按当前控制权条件接入，不抢占他人租约。已暂停或安排重连时，在途轮询返回只做收尾，不再执行停止及就绪上报。手动暂停取消待重连任务，联动存档期间延后重连。认证、身份或持久化错误仍按各自明确错误处理，不伪造可用状态。

`FENCE_STALE` 表示旧写入控制权失效，不清除用户已启用席位的运行意图；无论发生于续租、就绪上报还是决策执行，均停止旧凭证写入，并按 15 秒递增至最高 300 秒的退避重新接入。接入沿用身份与房间校验、未决账本查证和有界租约等待；发现其他执行器持续续租则停止，不执行 takeover。身份、授权、房间或会话失效（`LEASE_LOST`）不按普通失租重试，手动暂停与关闭仍取消自动恢复。

恢复先刷新授权事实并查未决操作，不重复已接受命令。模型请求的 unknown 与游戏写入的 unknown 分开：完整响应未被接收就没有可执行工具；恢复模型生成不授权重放远端写入。进程崩溃遗留的 pending dispatch 按持久诊断保守处理，不能只凭调用计数重新付费请求。

回执观察投影保留未决写入及本轮尚未核对回执所需的确认事实，直到已接受回执与不再需要的投影清理在同一事务提交。保存失败或本地版本冲突不提前清理内存证据。恢复时先验证整轮检查点的房间、玩家与完整性，再按其精确命令 ID 从原始持久回执补回被省略的接受事实；预约、舰队观察或未知核实结果不遮蔽原始成功确认。缺少可靠身份与回执证据时保持未知，不恢复历史完整观察，也不重新发送操作。

## 人工命令和诊断

启用 manual-commands 能力时，人工接受事实由服务器提供。控制器遵守当前保护和局部冲突，不能把人工操作推测为玩家确认的战略指令。普通决策只确认实际提供并核对的原始回执。

诊断记录操作阶段、请求编号、错误类别、scope、时点及安全原因，不打印凭据、模型密钥或隐藏世界。运行报告分别统计模型失败、工具拒绝、写入未知和真正致命停席。

停战发起或接受先持久化已评估的冲突舰队与返航损兵依据，撤回批次全部成功确认后才提交协议。整批准入核对完整舰队清单；逐条提交时，执行器提供当前子命令和前序实际成功回执，仅允许已成功撤回的前缀退出待撤集合，并重新核对其余舰队的损兵、回收点和在途风险。缺少前序回执不能凭舰队消失认定已撤回。未知结果沿用原批次查账，不重复撤回或签约；成本、范围、回收点或对方在途风险变化使旧意图失效。部分撤回失败不提交，已结算损失保留。生效后遗漏冲突舰队经统一返航意图与回执链处理，不能绕过人工和指挥官保护。 禁止目标不阻止己方舰队返回当前己方据点；返航点失守或不再属于己方时仍按原目标约束校验，返航权限、损兵、人工和指挥官保护继续独立检查。
