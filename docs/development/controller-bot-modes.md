# AI 控制器与 bot 模式架构

## 目录与责任

官方 hybrid 是随包提供的源码插件，经统一目录加载器安装；模型是否配置仍是 hybrid 的运行能力。本机控制台可加载独立文件夹中的 TypeScript 插件，也可通过源码注册独立程序、模型主导或混合策略，复用同一运行基础，详见[AI 本地插件与源码扩展](ai-extensions.md)。

| 目录 | 责任 |
| --- | --- |
| `application/` | 实例组装、配置、控制台、供应商传输 |
| `plugins/hybrid/src/` | 战略、外交、指挥官转译、约束、前台与后台协同 |
| `controller/local/` | 本地自主轮次、计划连续性、回执与侦察记忆、工作线程 |
| `controller/analysis/` | 战术候选、有限搜索、风险和资源计算 |
| `controller/runtime/` | 调度、观察刷新、就绪、执行循环 |
| `controller/execution/`、`storage/` | 权限、人工保护、原子保存、账本、查账恢复 |
| `prediction/` | 授权观察上的条件推演与共享计算 |

## 模式内流程

未配置模型且没有已发布任务或待恢复操作时，hybrid 使用本地自主规划。模型已发布任务、约束或未决操作时，前台按其规划与恢复，禁攻、留守、人工保护仍生效。未解析的新指挥官正文使自主下令暂缓，前台完成就绪，世界继续推进。

配置模型后，后台异步发布战略、任务和外交消息；后台没有游戏写入权限，也不阻挡世界推进。前台的搜索、当前版本复核和实际执行分开，搜索可跨 tick。详见[分层协同](hybrid-bot-guide.md)。

## 统一模式协议

`BotModeDefinition` 定义能力、配置校验及每席位实例工厂，`BotMode` 是控制器注入接口；默认目录提供官方 hybrid。观察、调度和执行器依赖接口而不导入具体策略。测试仍可注入未注册的脚本指令源验证公共执行状态机；玩家扩展通过源码注册或宿主本地插件目录接入。

`prepare` 提供前台步骤；后台通过 `createBackground` 接受授权观察并管理取消和排空。`beforeExecute` 在提交和批次子项前复核当前战略约束，不替代共用权限校验。模式私有记录使用 `mode-<策略标识>` 命名空间，不能冒充工具回执。

本地规划只提出指令，统一执行器负责解析、身份、版本、人工保护、资源、账本与回执。未知写入先查原请求，不换身份重发；命令接受不代表抵达或成功。

## 注册模式

宿主启动创建空注册器，经 `application/plugin-catalog.ts` 加载运行目录中的插件快照；首次安装 `plugins/hybrid/` 中的官方策略。省略 `mode` 时默认使用已加载的 hybrid；只接受源码注册或宿主已加载的标识。`provider: programmatic` 仍拒绝，纯程序策略不是供应商种类。供应商位于 `application/providers/`，不属于另一套 bot。模型传输返回原始 JSON 与用量，策略和指挥官通道各自解析业务输出；本地计算使用独立准入接口。

## 构建约束

`npm run check:boundaries` 检查静态、动态和类型导入。controller 禁止依赖 application 或具体策略；模式禁止依赖 application，也不能借包总入口绕过边界。共享确定性规则放 controller 或 prediction，不复制到供应商或 UI。

## 运行约束

本地规划保留进攻初筛、风险、内部调动、计划连续性和侦察回执记忆。后台模型使用的事实、约束和条件计算不能取代真实结算；关闭模型也不撤销已经发布的限制。搜索预算与评分参数见[本地战术规划](tactical-planning.md)。

独立分发包不包含仓库参考组装 `reference.ts`。该入口仅供嵌入式开发场景和回归测试显式组合源码策略，不能作为发行宿主的策略回退。打包输入检查见[宿主与插件分发](bot-distribution.md)。
