# 本地战术规划

## 运行与参数

在分层协同控制台的策略参数中配置本地战术。未配置模型时使用完整自主规划；已发布战略约束时，规划遵守有效任务与执行守卫。本地搜索不增加模型调用或 Token，用独立决策审计记录。固定槽位持久保存设置，显式配置模式只对本进程应用网页改动。

规范配置位于 `settings.bot`，格式标记为 `schemaVersion: 2`。省略数值采用默认值；未知字段、未知版本、越界、非有限数或混用字段拒绝，不截断。完全省略 bot 配置采用默认值；无版本输入的既有规范化边界以 `packages/contracts/src/bot-settings.ts` 为准，新示例只写当前格式。

| 字段 | 默认 | 范围 | 作用 |
| --- | --- | --- | --- |
| maxSimulations | 80 | 2–512 整数 | 条件推演尝试数，含基线与压力场景 |
| maxElapsedMs | 4000 | 1000–60000 整数 | 协作式计算预算，毫秒；主搜索各场景统一使用此值 |
| horizonTicks | 196 | 1–196 整数 | 联合推演窗口，世界日 |
| reviewIntervalTicks | 6 | 1–144 整数 | 距最近一次实际搜索的定期复查间隔；有无模型均采用，控制台不提供此项单独编辑 |
| minActionGain | 1 | 0–20 | 所有自主候选统一的加权收益门槛 |
| minCaptureGain | 1 | 0–40 | 保留的序列化字段，不参与行动准入；网页不再提供独立攻占门槛 |
| objectiveSwitchTolerance | 6 | 0–50 | 合法旧目标的收益容差 |
| forceBufferRatio | 0.4 | 0–1 | 参考兵量的额外余量 |
| remoteUncertaintyForceFraction | 0.35 | 0–1 | 满足限定条件的远处未知投入上限 |
| economyWeight | 1 | 0.25–4 | 经济偏好 |
| defenseWeight | 1 | 0.25–4 | 防守与暴露偏好 |
| territoryWeight | 1 | 0.25–4 | 领土和夺取偏好 |

三项权重独立，不归一化。执行经济基准为 2，显示/保存的 1:1:1 对应有效乘数 2:1:1。1 兵在基础兵力分中计 1 分，其他资产为启发式等值；门槛不是实际兵数或胜率。参数不能跳过权限、资源、可见性、生存或终局检查。

本地战术规划按当前授权总兵力（含在途兵力）除以当前容量计算占比 r，限制在 0–1；容量为零且有兵时取 1，无兵时取 0。占比不超过 50% 时保留基础偏好；50% 至 100% 之间，以 `p = (r - 0.5) / 0.5` 连续降低进攻兵力机动机会成本，乘以 `1 - 0.5p`，满兵时保留基础值的 50%。容量压力不再降低攻占收益门槛，所有自主行动共用 `minActionGain`。守备缺口成本、出兵余量、未知投入上限及战斗与压力核验保持各自规则；不能仅为腾容量送兵，出兵本身仍占容量。每轮及提交前复核使用当时观察重新计算，决策审计 `policyDiagnostics.attackPressure` 记录当前占比与有效值。

```json
{
  "mode": "hybrid",
  "provider": "offline",
  "model": "",
  "personality": "schemer",
  "bot": {
    "schemaVersion": 2,
    "maxSimulations": 80,
    "maxElapsedMs": 4000,
    "horizonTicks": 196,
    "economyWeight": 1,
    "defenseWeight": 1,
    "territoryWeight": 1
  }
}
```

## 决策链

搜索和提交前复核共用最多八个搜索协调线程；正常完成后保留线程及已加载模块，每轮重新传入授权观察、约束和预测上下文。各轮消息按独立任务标识隔离；取消、超时或崩溃时销毁相关协调线程，后续任务按需补建。预测计算继续使用独立的有界预测池。提交前复核只检查选中原方案，预算为 2 秒、最多 32 次模拟；超时不继续使用未完成方案，已有完整检查点仅按原有规则返回。

程序只生成当前立即提交的操作组。运输后的开矿、集结后的出击和不同出发时刻的协同，等待后续授权状态更新再判断，不预登记整条未来指令链。条件预测仍可分析未来时点。

1. 读取本人授权观察、未决结果、玩家预约与本模式目标笔记。
2. 生成己方内部富余兵力调动及等待、进攻、防守、开矿、有限侦察和组合候选。内部调动仍检查来源守备、归属路径、资源、手动保护、完整交付和生存，但不再通过独立低收益旁路提前执行；所有自主候选在同轮预算内按统一加权收益比较。拒绝或未知结果不重发。
3. 在统一预算内分配发现、细化、组合与最多四个初选方案的敌方压力验证，另允许一次受反夺否决后的子组合重评；每席位默认每批至多五个候选，所有席位共享[运行说明](ai-runtime.md#调度)中的有界预测池，结果按稳定顺序合并。进程池扩容不自动扩大每席位批次，避免慢分支推迟整批检查点。发现阶段先保留真实来袭的防守响应，再用发现预算约40%、最多八个候选覆盖普通主力直攻：优先战略指定目标及可投入兵力较多的来源，先比较不同来源和目标的估算兵量，再尝试更高投入；之后按候选类别轮流检查其余候选。此排序由程序化与 hybrid 前台共用，不改变行动收益门槛或战斗验证；有限预算仍可能留下未检查方案。
4. 先比较存活/终局类别及实际冲线时点，再比较软分、门槛和目标保持容差。
5. 返回正常指令信封，经控制器统一执行与回执核对；本地规划器不直接写玩家接口。

普通收益差为候选普通评分减去同轮等待普通评分；压力收益差为候选最差已测试压力评分减去等待的对应压力评分。统一综合收益差为 **60% 普通收益差 + 40% 压力收益差**，默认须严格超过 **1 分**。进攻、防守、返航、开矿及内部自主调兵使用同一规则，不再设置防守损失上限特例或单独的普通/压力收益双门槛。权重是风险偏好，不是反击概率。未生成额外压力场景时，两项均使用普通评分；需要压力检验而未完成时不得把缺失分数当零或退回普通分准入。普通和压力场景各自的存活/终局类别及冲线时点不得因软分变差，已确认的终局改善仍优先。已通过准入的备选方案直接比较加权评分，不重复收取门槛；开局覆盖偏好与显式目标保持容差继续在合法候选中适用。决策审计 `policyDiagnostics.selection` 保存权重与门槛。

组合搜索交替比较不同目标的两项行动、同目标两至四个来源的联合进攻，以及最多三个组成部分的联合方案，整组不超过八条立即指令。组合种子不要求单独过收益门槛；单独未能占领的来源可以组成新进攻，但组合必须从头完成整组资源、目标路径和敌方反应检验，不继承单项的成功、失败或评分。重复修改同一舰队、同一来源与目标的兵量替代项，以及确定重复占用当前兵力的纯出兵组先行排除。

组合尝试上限为总模拟预算的 25%、最多二十次，与发现、细化和压力检验共用预算；发现补充候选后允许再次形成组合。每次尝试保留实际生成的反应场景额度，时间和总次数保护不变。组合与关键防守响应保留有限压力比较位置；采用组合须通过统一加权收益门槛，不因指令更多而加分。审计中的 `searchEfficiency` 记录组合尝试和消耗收益上界拦截次数。

多目标立即进攻因部分目标在条件反夺中未能持续持有而被否决时，预算允许则移除该方案中这些目标的全部出兵波次，最多重评一个非空子组合；不会拆分运输、开矿、返航、消耗或未来时点的依赖操作，也不改写提交前复核的精确原方案。子组合重新计算普通资源与路径，并执行原来共享集合中的全部压力场景，与同场景等待基线比较，不继承原组合的评分或兵力估算。已有完全相同且完成压力检验的候选不重复重评。初选阶段可为此保留一次普通评估及完整压力检验额度，预算不足时减少初选数量而不删反应场景；时间不足、未知或检验不完整时不采用子组合。生存、终局及相较等待新增失矿的原有检查继续适用。`searchEfficiency.holdingSubplanAttempts` 记录这一次独立恢复尝试，总模拟和时间上限不变。

实际时间预算受机器负载和单次同步推演影响，不是硬实时响应保证。固定输入与模拟覆盖下可以复现；时间截断可改变覆盖。

每次规划协调任务在派发候选前捕获一次完整授权观察，完成序列化、内容摘要和独立副本准备。发现、细化、组合及压力测试的后续批次共享这份私有上下文，只提交候选差异；调用方后续修改观察不会改变已捕获材料。准备上下文与推演结果缓存分开：跨席位、跨轮及实际观察变化仍保持原有隔离，执行前复核使用自己的当前观察上下文。取消、公平排队、缓存容量和搜索预算不变。

内部候选的初步核验最多先使用约 24% 的规划模拟与时间预算。通过完整路径、资源、归属及生存核验后，继续进入同轮统一加权比较与必要压力检验；初步核验通过不等于已经采用。内部与普通候选共用本轮总预算。

内部兵力调动只考虑己方来源与目的地：按可见缺口补防，或从安静后方送部分富余兵力至已知前线；预约占用与来源守备保留。不超过三个内部操作可组成一次联合候选。完整预测窗口内必须确认友方交付和所需归属路径，不能确认则保留原状；通过后仍须达到统一加权收益门槛。模型发布的返航意图同样进入收益比较。玩家已确认的指挥官一次性指令继续使用既有执行权限及安全检查，不以自主软收益取消明确指令。实际抵达仍以回执和结算为准，有限检验不构成全局安全保证。

## 经济与持矿评分

进攻的削弱收益按对手公开胜利压力加权。全部活跃玩家（含自己）之间按公开静态胜利时钟排序，采矿模式使用当前库存和日产量计算距目标的时间，无收入时以库存排序；占领模式使用据点数。并列取平均名次，归一化排名分为 0–1，只有一个活跃玩家时取 1。权重为 `0.4 + 0.8 × 排名分 + 0.6 × 胜利紧迫度`；采矿紧迫度从距胜利 288 tick 至即将冲线线性升至 1，占领紧迫度从胜利要求的一半至达到要求线性升至 1。排名靠后且距胜利远的对手获得较低削弱分，自己的新增领土、经济及生存收益仍单独计算。静态时钟不代表真实获胜时间。

完整条件路径中明确记录的敌军兵力损失乘以上述权重，形成 `enemyAttrition`；己方损失仍由终点兵力分扣除。护盾消耗、未知战果和第三方互相交战不计入此项。攻占敌方设施的 `denial` 使用同一权重。当前总兵力达到容量的 80% 后逐步增加 `capacityPressure`，满兵时系数为 0.35；计分数量取真正腾出的容量、敌军损失和当前可见工厂在预测窗口内的产能三者最小值。超过容量的部分先抵扣己方损失，单纯发舰不腾容量，此项是有界偏好而非已实现产量。

每个授权可见敌方目标另从最近可用来源生成一个有限消耗种子，投入至多为当前总兵力的 25%，与占领方案共用模拟预算。有限消耗采用同一进攻收益门槛，兵力机动成本保持原值。新出兵先计算保守净交换收益上界：全部活跃对手的最大价值权重、有效夹击奖励上界和产能释放奖励上界，共同限制这支舰队可能获得的损兵收益。只有上界仍可能严格超过实际门槛时才继续推演；途中可能与其他敌军交战，不能只取目的地对手的权重。既有舰队修改不使用该新出兵上界。此类候选不要求最终占领，但必须在新出兵的明确战斗中造成敌军损失，加权交换收益须超过自身战损与行动门槛，再经过资源、来源风险、禁攻约束、终局和有限敌方反应验证，并在统一加权评分比较中优于等待。当前不将消耗候选与其他候选自动组合；没有占领不算完成夺取任务。评分不代表胜率，也不保证有限搜索会覆盖或选择某次袭扰。

### 开局中立点分配

第0至143世界日，程序化与分层协同共用开局分区。按环形地图几何距离比较已知己方、存活对手据点到每个中立点的最近距离；差距在0.5地图单位或较近距离10%以内时视为争夺点。区分己方近点、对手近点、争夺点与归属资料不足的未知点，距离不等于实际ETA。隐藏兵力不补零。

正常扩张或筹备经济、且没有实际己方来袭时，同一终局类别与时点下，优先比较可行方案对己方近点的覆盖，再比较其他收益。路径、资源、生存、行动收益门槛及有限对手反应核验仍须通过，已有确定终局时机和实际威胁不被开局偏好覆盖。联合候选最多一次分配八个不同己方近点，各来源共用安全余兵预算；已有足量己方舰队驶向目标时不重复生成覆盖任务。在途覆盖不是已经占领，位置奖励只按条件终点实际控制的不同目标计一次。

普通空中立点以当前可见守军和护盾估算最低占领兵力。对手近点与争夺点另以最近对手的可见部分驻军、实际可见敌方在途兵力生成竞争兵力种子，可能需要更大投入；这不是敌方实际驻军或未来命令。有限反应场景可让一个对手尝试先占中立点，再由共用引擎检查争夺；没有可见兵力或可用路线时保留未知。已被占领或开局阶段结束的目标转回普通进攻流程。

评估区分条件终点的真实模拟矿量 `neptunium` 与未来完成时间偏好 `miningPotential`，后者不是预测收入。

同一观察上的候选共用参考窗口 R：有当前收入时采用静态完成时间，无收入时采用当前领土下单矿时间，并受可得对手公开静态 ETA 约束。候选完成时长 D 由推演已过时间和剩余目标/折减后收入构成。矿场时机选项值为：

`目标 × 矿量权重 × R / (R + D)`

无有效折减收入或已达目标时不给额外选项值。局部守备、已知来袭、附近可见压力及未知限制影响持有折减，但不是存活概率；实际失矿扣款只由引擎计入。库存暴露、来源守备缺口和矿损偏好分别保留，不能把这些分数当互斥现金账本。

新增开矿额外计入兵力投入占比：以本轮当前己方总兵力（含在途兵力）为分母，将新增建设费用合计除以总兵力得到 r，限制在 0–1。新增矿场的持有信用乘以 `(1-r)²` 后重算完成时间偏好，差额作为 `mineForceCommitment` 扣分。例如费用 50 兵、总兵力 160 兵时，新增持有信用保留约 47.3%；总兵力 500 兵时保留 81%。这只影响价值评分，模拟库存、实际收入、原设施损失与局部防守仍按原计算。已有矿、抢占已有矿和本轮开始前已经付款的建设不重复扣分；预测中后续产兵不能稀释当前投入占比，确定终局结果仍优先。

产能按有界窗口和容量压力估值；没有有效工厂产能时，不给纯供电额外生产价值。等待、保留产能、筹兵开矿、直接开矿、抢矿及补防共同参与比较，不设固定“满兵才能开矿”条件。

## 兵力与未知

### 局部风险与兵力调动

模型初筛、程序 bot 和分层协同的战术规划共用 `controller/analysis/outpost-risk.ts`。风险按本人授权观察计算；未知兵力保留为 unknown，不填成零兵或已确认安全。周围敌方兵力的合计表示潜在压力，不表示多个玩家已协同出兵。

按预计抵达时间选最近两处有可调兵力的同阵营支援点，时间为 T1、T2。守军估算为本点可用兵力、当前护盾、T2 内能抵达本点的己方在途兵力之和，再加第一支援点可调兵力的 0.5 和第二支援点的 0.2。敌军估算为 T1 内可抵达的可见敌方兵力，加 T1 至 T2 内兵力的 0.5。缺少支援点时，用有界观察窗口补足时间边界；完全没有支援时仍计算窗口内敌军压力。

预约兵力从己方可用库存扣除；在途兵力只计现有目的地，不假设舰队可以改向。路线使用环绕地图及当前世界时间对应的普通航速；既有普通航速矩阵可复用，交战、未来命令与归属变化仍须联合推演。

压力比为 `敌军估算 / max(守军估算, 1)`，估算缺口为不足部分。矿点的优先分乘 1.5；这些系数不改写实际兵数。另按已观察舰队的抵达顺序检查缺口，同 tick 保守地先算敌方抵达；晚到援军不能消除更早的缺口。输出包含压力比、缺口、支援来源、最早缺口时间和未知原因，均是静态估算，不是胜率或安全证明。

留守偏好、终点暴露评分和持矿折减共用此计算。风险扣分以缺口为主，并保留一项有界的连续压力代价，使尚未出现缺口时的兵力调动也能比较位置风险。抽兵同时扣除各来源的合计兵力，重新评估全部己方据点，包含其对邻点支援能力的影响。该成本与条件终点评分分别衡量出兵期的机动损失和预测局面，不作为互斥损失账本。

程序化与分层协同的进攻及敌方反应路线均使用144 tick窗口。矿场压力按每处矿场选择评分最高的两个可达对手，各自最多两个来源，分别以65%和100%可见驻军独立推演；全兵分支是压力假设，不表示敌方会实际出兵。决赛方案和留守必须覆盖同一组反应分支，预算不足先减少决赛方案，不静默省略其反击场景。路径中出现相较同场景留守新增的己方失矿时，普通扩张分不能抵销；只有确认改善终局结果或同类终局冲线时间才允许例外。终点夺回也不能抹去中途失矿。有限压力分支不穷尽所有反击，未验证的路线不表示安全。


内部调兵优先补实际来袭及高风险点，再将安静后方的部分富余兵力前送。每个来源只分配一次，多个来源共用目标剩余缺口；最多三项内部调兵联合核验。分配过程中重新估算整体风险，假设交付后的整体风险变差则不进入内部调动短名单；交付假设不作为事实，途中归属、抵达和生存仍由共享预测核验。进攻常规目标按最近抵达时间默认限前十个，矿点、已有舰队行动、本轮直接关联与显式查询的目标额外保留，候选仍需完整战斗推演。

风险参数独立于游戏规则和席位偏好，由 `AI_OUTPOST_RISK_CONFIG` 指向 JSON 文件。示例见 [ai-outpost-risk.example.json](../../config/ai-outpost-risk.example.json)；省略时采用源码默认值。`firstSupportWeight`、`secondSupportWeight`、`outerEnemyWeight` 默认分别为 0.5、0.2、0.5，范围 0–1，第二支援权重不能超过第一支援。`mineMultiplier` 默认 1.5，范围 1–10；`horizonTicks` 默认 144，范围 1–144 整数世界日；`targetLimit` 默认 10，范围 1–100 整数。未知字段、非有限数和越界值拒绝。初筛与每轮规划读取配置；报告缓存包括这些参数，已在运行的单次规划保持自己的参数快照。

压力验证短名单最多保留四项候选，与等待及相同压力场景比较，仍须通过资源和生存检查。

进攻反应推演按短名单中的每个目标分别生成补防与占领后反夺场景，使用同一对手在计算窗口内能够抵达的全部可见来源，每处动用当前驻军的 65%；不同玩家分别测试，不合并为协同军队。窗口默认 144 世界日，包含己方出发、敌方反应及双方抵达时间，已有舰队和己方后续增援共同结算。常规扩张中，反夺场景终点未持有目标的候选不作为占领方案入选；阻止已预测对手冲线的短暂夺矿仍按终局结果单独比较。压力测试覆盖不完整时不采用候选，不以减少场景掩盖预算不足。仅使用可见兵力，不预测未观察的援军或未来命令。

### 出兵

默认出兵余量 `forceBufferRatio` 为 0.4。参考兵量 n 的余量为 `n + ceil(n × forceBufferRatio)`。它是候选种子，不是固定留守比例，必须实际付得起并通过推演。目标保持仅适用于仍优于等待、胜负类别及终局时点一致的合法候选。

未知不补零。远处未知例外只在路径、目标占领证据、存活、来源及未知类别全部符合时成立，草案累计兵量受该比例约束并扣风险分；比例不是一般成功概率。单兵侦察使用独立条件，记录已尝试目标。

## 执行边界与扩展

只使用本人真实回执恢复操作，不凭舰队消失记成功。bot 只提交当前操作，不生成未来预约或取消预约；未来行动在后续唤醒时重新判断。自然语言外交、联盟和自由文本指挥官执行不属于此模式；隐藏功能继续关闭。

战术候选、评估与工作池位于 `packages/ai/src/controller/analysis/tactical-*.ts`，本地轮次、计划记忆和回执处理位于 `controller/local/`，hybrid 是唯一产品策略入口。边界见[模式架构](controller-bot-modes.md)。

离线诊断使用 `scripts/diagnose-bot.mjs`，隔离对战使用 `scripts/benchmark-bot.mjs`。具体参数以脚本用法为准。比较策略须固定版本与预算、轮换出生位置和多个种子，同时观察终局、持矿、损失与有效操作；单局胜利不证明整体强度。

战术复查由观察器检查最近一次实际搜索的完成时间：达到席位配置的 `reviewIntervalTicks` 时触发，默认 6 tick，有无模型均采用此值；其他有效事件仍可提前唤醒。结束轮次和核对回执不重置该时间；活跃维护单独安排。详见[分层协同 bot](hybrid-bot-guide.md)。
