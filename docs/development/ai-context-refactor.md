# 模型上下文规范

## 分工与一轮流程

程序提供玩家有权知道的确定事实、状态变化、实际回执和条件计算。模型负责解释战略意义、制定目标和外交选择。不能用推理补事实通道，不能凭舰队从观察列表消失判断抵达或被摧毁。

hybrid 后台按指令转译、外交和战略职责整理整轮材料，一个或多个触发原因共同唤醒。模型返回语义意图编辑、战略记录及外交消息，不通过旧式工具链直接逐步下游戏指令。前台程序执行有限战术搜索和统一校验。实现为 `plugins/hybrid/src/brief.ts`、`intent-protocol.ts` 与 `background.ts`，详见[分层协同](hybrid-bot-guide.md)。

前台每轮执行一条行动或一个行动批次后，直接通过程序处理回执、保存计划记忆并结束，不再为收尾或追加行动再次规划。后续行动留待下一轮触发；新增事件保留在唤醒队列。执行前校验、失败处理及结果未知时的查账仍按原规则进行，批次内各操作继续分别记录回执。

前台每 tick 入场时固定一份规划材料。同一房间、席位及 tick 内，后续状态版本、消息和观察次数变化不打断规划，也不再次读取观察来竞争准入；后台来信和外交仍继续处理；前台完成后普通新事件留在服务端，下一 tick 合并读取分析，不为刷新就绪重复收集。非实时对局跨 tick 或身份变化使旧方案失效；实时对局不因跨 tick 本身丢弃本轮行动，仍在执行前核对当前事实。实际提交被拒绝时结束本轮，不在同轮重算。原触发原因和复查要求保留，托管调度允许当前 tick 正常就绪推进；未决操作继续查账。执行前仍读取必要的当前事实并校验方案、人工操作、指挥官约束、兵力、归属和权限。即时出兵和返航可通过 `actions.scoped-revision/1` 提交原观察对应的行动依据摘要；服务器在准入和结算时重算相关依赖，无关区域的驻军或已知其他目的地舰队变化不再单独导致版本拒绝。非实时对局的摘要保留同一 tick 和己方资源、相关单位与约束，跨 tick 或相关依据变化仍拒绝；实时对局（包括开局倒计时阶段）的即时行动按提交时当前状态判断是否合法，旧版本或旧摘要不单独阻止提交，仍校验当前兵力、归属、人工优先级、指挥官要求及控制权限；固定规划材料不代表方案保证可执行，不能将新事实改标签成旧规划依据。

## 常驻内容

hybrid 战略、外交与指挥官转译的固定提示词维护在 `plugins/hybrid/src/prompts.ts`；通用指挥官讨论与整理、普通规则及采矿阶段说明维护在 `controller/presentation/game-prompts.ts`，由 hybrid 引用。`brief.ts`、`commander.ts` 负责准备动态授权材料并调用这些模板；`model-wire.ts` 和 `intent-protocol.ts` 负责响应结构、归一化与严格校验。提示词中的规则数值与输出限制继续引用规则库和协议定义，不另行维护副本。固定说明只按职责与服务器合同协议能力编排，开局、待签提案和履约状态不再增删固定规则段落；规则用条件句解释不同阶段，当前开放动作及引用由动态权限清单提供。未签提案直接提供本方是发起方还是接收方，不要求模型从聊天语气推断签署权限。

程序提供授权全局概况、当前目标和执行约束、已确认指挥官正文、实际反馈及当前职责所需材料；通用进攻初筛保留在程序侧，不常驻发送候选。`executionFeasibility` 列出任务等待时长、执行原因、当前保留的关联操作和期限；夺取任务另列静态最低突破兵力、初筛需求、投入上限差距与航程，指定运输另列来源安全可调估算、留守、保护与执行窗口。关联操作仅代表当前保留范围，不把空值当作全历史未行动。防守未知保留 null，静态与初筛数字不保证实际胜负；模型据此比较调整投入、改目标、集结或取消，不能仅续期来描述策略进展。外交仅提供当前会话可编辑任务的这份反馈，独立战略和其他合同的编辑边界保留。具体信息按整轮问题展开；任务状态由程序维护，模型战略不是当前事实。讨论提案不是生效指令。

规则提示只保留影响战略取舍的后果和当前职责必需的输出约束。生产与采矿进度、护盾恢复、取整、抵达排序、调度锁和签到等计算或执行细节由程序维护；模型使用已提供的费用、收入、任务执行差距、相关目标判断与条件预测结果调整战略。建矿替换设施的机会成本、失矿扣库存、返航损兵和合同义务仍须说明。按实际开放能力引用预测材料，不向模型介绍未开放的直接预测工具。

据点使用授权完整名称；未知或重复名称拒绝，不模糊匹配。舰队使用稳定代号，不能与预约混用。事实、条件估算、评分建议和未知分别表达，不能把有限搜索写成全局最优或胜率。

## 工具集合

前台统一执行器只保留 `order`、`batch`、`say`、`notebook`、`reminders`、`finish` 六个内部操作入口。它们供控制器校验和提交，并不是后台模型的逐步调用目录。模型响应的浅层结构由 `model-wire.ts` 从内部 schema 生成；模型输出先确定性转换，再通过 `intent-protocol.ts` 的内部语义与权限校验。模型 tasks 为扁平对象数组，cancel、外交动作及指挥官约束字段放在顶层，不要求模型拼装内部执行器对象。

预测、比较、路线、初筛和资源检查由程序直接调用共享库；保留程序化进攻初筛和预计算。不存在模型历史 recall 或独立查询工具链。原始审计、真实回执、原子保存与内部校验继续保留。

Gemini 的生成侧约束设计、复杂度边界与实测验收见[结构化输出规范](gemini-schema.md)。供应商接受 Schema 不替代内部语义、权限和发布依据校验。

通用模型结果固定返回 `summary`、`tasks`、`cancel`、`reviewOn`，无内容时使用对应空值。任务结构按动作区分必填参数，返航仅使用舰队引用；模型不需要填写其他动作的占位字段。

`fixedModelResponseSchema` 按职责和服务器合同协议能力生成固定结构，保留各动作完整字段分支、类型、数量及数值界限，不嵌入据点、舰队、任务或合同身份枚举，也不因当前无任务、无舰队或无已签合同删除动作分支。Codex 与 Gemini 从这份固定结构生成各自投影。`intent-schema.ts` 的共享构造器另生成程序专用的动态授权契约，经 `model-permissions.ts` 编译为 `facts.permissions`；该授权契约不发送给模型，不与固定生成结构混用。内存中的请求参数包含同一份 `prompt`、响应 Schema 和本地 `audit`；持久调用日志的正文按[调用保留窗口](persistence.md#控制器私库)保存，窗口外仅保留摘要、指纹、用量和校验审计。`audit` 不发送给模型，适配器再将正文与 Schema 转成实际供应商请求。兼容接口在一条当前 user/input 中保留完整 prompt，JSON 对象与纯文本模式将完整 Schema 追加在 prompt 末尾；原生 Schema 模式使用结构参数，不重复插入正文。Gemini 将完整 prompt 放入当前 contents，Codex 按既有完整分段边界分离开发者规则。每次仅发送当前轮，不附加旧模型回复或旧局势。

## 同轮资料与变化

模型回复不因观察版本、tick、据点结构、来袭、后续消息或新排队评审发生变化而自动作废。返回后按当前事实、权限和合同状态尝试发布；仍合法且无冲突就应用，实际冲突或非法内容整份丢弃，保持本轮任务、消息和合同操作的一致性，不拆分拼接回复或自动调用模型修复。房间、席位、玩家已确认指挥官要求及暂停取消边界继续校验。新消息留待后续轮次，成功发布只确认本次实际展开的消息和回执。未发送任务仍按最新材料准入，避免发送已被替换的请求。

后台可以将不同正式协议意图依次存入现有待执行列表，相同动作复用原记录；另一条命令待回执本身不使整份回复发布失败。程序在实际执行时按当前事实复核并串行提交，实际回执立即更新本地状态；未知结果保留原身份查账。入队不代表签署或履约已经发生。

`facts.permissions` 保留本轮可用任务种类与各自目标、来源、集结点或舰队范围，可编辑及可取消任务身份、任务数量上限、当前可见据点、指挥官约束引用、本人有效协议身份及当前会话的提案和响应权限。空清单不授予任何引用，当前无可编辑合同时上限在权限清单中为零；返航只提供程序确认 `canReturn=true` 的己方舰队，集结点只允许当前己方据点。新目标不包含视野外或已毁据点；既有笔记、合同和原文中的旧引用不能扩大新行动范围。未知、终态或过期任务身份不开放编辑。当前会话只有一个已确认对手时，程序可将新提案省略的 peer 绑定为该对手并记录归一化审计；显式错误身份不改写，对手不唯一或未知时不补值。外交确定事实和权限清单共用同一身份映射来源。权限清单与当前上下文同轮更新，不作为可复用 thread 的固定指令。

任务期限使用动态材料中的当前世界日，固定规则要求 `until` 严格位于未来；生成 Schema 保留静态数值范围，不嵌入每轮变化的当前时间下限。发布前程序仍依据最新授权观察拒绝已到期任务，不补写、延长或猜测模型期限。合法任务身份、据点、舰队、外交动作和合同范围由本轮 `facts.permissions` 明确限定；固定 Schema 中存在某种动作或允许字符串不授予编辑权限。程序在格式与归一化处理后核对捕获的权限清单，并在发布前重新依据最新授权观察、任务来源及合同状态构造权限清单再次校验，任何一项失败都不发布本次任务、战略、消息或合同操作，程序审计继续保留。待签提案在推理期间已被合法接受时，只允许同一接收方对同一合同的接受成为无重复写入的确认；过期、终止或其他会话提案不适用。

后台调用在准入和发布前核对指挥官版本、任务版本和材料依据。模型回复未通过格式、语义或权限校验时整份丢弃，不追加错误说明让模型自动重试；原始调用审计、既有约束和未成功发布的回执消费边界保留。失败或不完整结果不替换有效约束；过时材料不得通过改标签伪装为当前事实。前台执行前再次核对实际授权观察与最新限制。跨轮战略通过笔记和语义任务承接，原始日志保留在私有审计。

Codex 在同一 bot 内按职责与稳定任务身份分别复用底层 thread：外交按具体会话分组，战略按原始思考任务分组；重试与超限拆分沿用所属任务身份，调用编号、尝试次数和 tick 不参与分组。调用前后的模型历史必须为空，调用中只允许当前一轮；完成后撤回并验证历史 `0→1→0`，再向控制器返回结果，失败则丢弃该分组的会话身份。thread 不承担跨轮记忆或历史回读，程序笔记、审计和真实回执仍独立保存。身份隔离、生命周期及用量口径见[运行说明](ai-runtime.md#显式配置)。

## 初筛、阶段与表达

初筛建议区分可行动、条件不足与已有行动，来源兵力、在途兵和后续产兵分开。程序提供搜索覆盖、风险和未知；AI 在配置模型时进行战略取舍。

采矿阶段按已观察到的里程碑推进；未知全局不能宣称无人开矿。压缩表格保留缺失、null、零、否及未计算的区别，保留实际时间、方向、归属和结果，不静默裁剪必要内容。时间单位见[世界时间契约](world-day-time.md)。

## 提示词分段与日志展示

后台战略、外交、指令转译和指挥官讨论在组装提示词时使用明确的分段标记。固定规则按职责与规则来源分段，动态材料按生成端的实际组成分段；控制台读取同一分段格式，不根据标题文字、JSON 示例或模型内容猜测边界。模型输入只保留简短的成对名称标记，例如 `[brief.global 全局局势]` 与 `[/brief.global]`，不写入格式、长度等展示元数据。正文若含有同名结束标记，生成端增加该段标记的方括号层数，保留正文原样并避免误拆。长度和原文范围由控制台按实际字符串计算，不依赖发送给模型的计数字段。

战略与外交的 `global`、`guidance`、`facts` 使用 `!model-data/1` 可读流式记录：字段和表头采用一一对应的中文语义标签，保留显式列定义及模型投影后的全部数值；少量行的宽表使用 `表[{字段:值}]` 逐项具名，避免合同双方额度、进度和达标状态依赖模型横向数列。解码后恢复原列顺序和表格。`?`、`是`、`否` 分别表示 null、true、false。字符串若与保留符号、数字或结构符号冲突则引用并转义；空字符串、空数组、零、否、未知及缺失仍分别表达。未知字段保留原名，不能猜测新字段含义。`model-data.ts` 负责严格编码和解码；控制台解码为具名视图展示，复制和字符统计仍使用保存原文。损坏、截断或无法解码的正文只显示原文，不展示部分恢复的事实。其他段及指挥官转译保留 JSON 表达，原始消息和已确认正文不改写。

`model-numbers.ts` 按完整字段路径与语义列定义整理模型展示精度，覆盖战略、外交、指挥官转译及私聊讨论。开局几何距离、静态获胜时间、竞争评分、压力比例及明确的候选/执行条件估算最多显示三位小数；小于该分辨率的非零量保留三位有效数字，避免变成零或改变正负。分类、候选顺序、真假条件及所有计算继续使用原始精度，显示相同不代表程序原值相同。不对任意数字或字符串统一四舍五入；当前时刻、合同期限、事件时刻、实际兵量、额度、进度、信任阈值、实际回执、已确认参数和未知新字段保持原值。编码器本身不修改数值。完整简报与审计保留原值，`contextSelection.numericPresentation` 记录实际调整的路径、原值和展示值，不发给模型。

`model-material.ts` 在编码前集中共同语义、消除逐值相同的重复字段及重复已选方案；新出现或不同的解释继续随材料发送。自身重复数值以玩家表对应行、建矿费以己方状态为依据；不同来源给出的胜利估算不相等时分别保留。编码不额外删除已按职责选择的程序结论、风险、当前任务、硬约束、合同与逐条实际回执；通用进攻候选和来源预算在入模投影前排除，完整计算仍供程序使用。

职责投影另外排除模型不使用的权限和程序审计字段：战略轮的合同表不携带外交提案动作、会话标记与合同专属编辑目录；没有原始消息、会话身份或通信事实时，玩家目录省略聊天身份，保留游戏身份和显示名。外交轮保留双方身份映射、提案响应权限、可编辑任务及目标范围。合同编辑与可行性列全部显式为 null 时可省略；有值的可行性、false、零及空数组不按占位删除，新出现的有效评估仍保留。消费边界累计计数只留程序侧，模型保留当前回执、授权窗口可用量及窗口外缺口；新回执数量仅在与逐条记录数相同时去重。完整简报、消费边界和发布校验不受这些模型投影影响。

战略、外交和指挥官转译的结构化舰队和合同引用使用从不可变身份派生的稳定短代号，例如 `F3-AA4FF248`；动态权限清单使用同一份冻结映射，固定响应 Schema 不含这些运行时身份。舰队类型依据当前舰队资料、显式舰队引用及已授权的舰队活动事件确认；出发、到达、返航、移除、战斗等记录的 `subject` 即使不再出现在当前舰队列表，也沿用同一代号，显式 `kind: fleet` 的目的地引用亦一致转换。事件身份、时间和结算内容保持原样，不因历史事件建立当前行动权限。未知事件类型和任意哈希不据此猜测为舰队。身份碰撞、与已有字面短编号冲突、跨类别冲突或原始正文明确引用完整身份时保留完整编号。模型输出只在行动引用字段还原身份，再进入原有语义、权限及当前事实发布校验。原始消息、理由和对外正文不做身份替换；完整具名简报和审计继续使用原始身份，不能用短代号视图替代内部校验。

每段计数包含头尾标记、正文和分隔换行，所有模块的原文范围连续且完整覆盖保存的上下文，模块字符数之和等于保存原文长度；另列正文与标记、分隔占用。JSON 美化后的空格和缩进不计入原文长度。原文、分段原文和复制全部使用保存内容，未知字段、null、零、false及空值不因展示而丢弃；结构化阅读视图隐藏空集合、空表和递归后为空的分组，数值零、false和null继续显示，原文与字符计数不受影响。未标记、截断或格式损坏的记录只展示完整保存原文，不伪造模块和缺失内容。

分段标记也是实际模型输入的一部分，计入原有上下文上限；不改变授权投影、固定输出 Schema、权限校验或结算依据。

## 容量

后台单次 brief 与指挥官请求上限为 60,000 UTF-16 字符，不能等同模型 Token 窗口。完整请求在模型派发前检查容量；重复引用及完全相同的消息记录无损去重，不合并不同消息身份或改写原文。外交保留全部未处理来信，超限时明确记录 blocked-context，不拆分后以摘要替换原文，也不递归拆分合并结果。其他职责仍按有界信息分块处理或报告无法发送，不截断指挥官正文或必要执行限制。模型 Token 按供应商报告统计；未知用量不得写成零。

## 外交事实

双向关系、当前竞争排名、正式合同的条款、个人占领目标、进度、期限、补贴与回执来自服务器授权观察。模型负责协商、战略取舍与是否背叛；聊天与内部笔记不能签署合同或判定达标。签署后程序自动投影履约目标，结束只处理其来源任务，指挥官等独立约束保留。固定 100/200 tick 与矿产补贴规则在外交提示词中共享定义，详见[外交协议](diplomacy-agreements.md)。

外交允许完成内部评审而不发消息，不因对方确认或主动复查就必须继续往返。程序在已授权具名投影上补充会话身份、名额知识边界及履约可行性条件；明确区分占领目标、当前静态成本、初筛估算、计划、真实出发和实际结算。对外表达的有界事实检查及纠错见[分层协同 bot](hybrid-bot-guide.md#外交与指挥官)，不能以抑制冗余为由删除未处理来信、阻止具体问题或禁止新的有效协商。

## 模型输入投影

`brief-projection.ts` 整理授权字段，`model-context.ts` 再生成模型专用视图。完整具名简报继续供外交断言与当前事实发布校验使用，不能以模型视图替代内部校验。模型正文删除存储身份、修订哈希、重复世界时间和指挥官版本；调用依据仍单独保留必要版本，内部完整依据不变。模型上下文按授权范围提供必要字段，不直接序列化完整观察或存储任务；不开放追加资料查询或由模型触发的补充调用。

正式合同按当前条款与历史结果分组，各组再区分停战和夹击。当前条款中 `proposed` 是待签提案，`active` 才是生效义务；程序预先计算双方剩余占领目标、剩余时间、固定达标奖励和假设当前到期的未完成处罚。当前合同内合并编辑权限与履约可行性，不在会话事实、风险义务和可行性清单重复复制同一合同数值。被正文、战略记录、任务、执行可行性或新回执直接引用的终态合同保留历史条款、实际终止时间及结果，移除当前剩余时间、剩余额度和潜在奖惩列；其余终态合同即使属于当前外交对象，也按对象、种类和履约结果汇总。历史仅覆盖当前授权合同列表，不保证全历史，也不可作为当前义务或复活旧提案。

据点目录为每个当前 `visibility=2` 的据点常驻提供完整名称、归属、类型、兵力与护盾；模型正文不携带可见性字段，缺失事实保留 null，不补零。`visibility=0` 和仅已知的 `visibility=1` 不进入模型地图目录、详情和新目标枚举。服务器公开地图仍供程序使用，不能把公开归属或坐标自动当作模型当前视野。当前任务按种类提供必要参数，运输明确来源、目的地和数量（含自动数量的 null），配置保留零值及 false。对手合同容量按表列出可见下界，组上一次声明实际完整占用及剩余名额未知；零下界不能解释为零占用。正式停战候选只按当前可见的双方据点分组，不让模型重新连接目录计算并集。

`model-vision.ts` 在模型分支中建立当前视野投影，完整程序观察、初筛与发布校验保留。开局目标与最近来源、距离及争夺分类按该可见子集重新计算，不能仅删掉视野外目标行后仍携带视野外的最近敌方来源。相关目标的模型进攻结论同样只依据可见子集；外交归属分组、可编辑目标、履约地图事实和指挥官讨论使用相同边界。条件方案中的视野外目标不通过动作元组、历史方向或替代方案重新带入；若已选方案被排除，其相对差异也不再作为可独立解释的方案提供。

原始来信、已确认正文、战略记录、既有任务参数、合同原条款和实际回执仍完整保留；其中的地点引用属于原文、义务或过去行动，不代表当前可见。既有任务目标在视野外时只保留任务及实际执行元数据，以 `outside-current-vision` 表达地图资料未提供，不附带其归属、兵力、静态突破需求或其他当前地图估算，也不能把视野丢失解释成失守或毁灭。可见舰队已有的来源/目的地引用属于该单位或己方行动事实，不据此展开视野外据点。模型调用审计另存可见数量及排除身份，不将排除目录发给模型。旧调用日志不回写。

战略和外交轮共用 `round-material.ts` 的整轮材料选择：明确范围、触发对象、来信提及、指挥官正文、关键资产和实际来袭确定需要的实体。相同对象合并保留原因；战略摘要提及地点、活跃任务存在、候选列出来源或共享舰队端点本身均不触发周边资料展开。触发直接指向任务身份时，仅补入该任务的目标、来源或舰队；只读任务在已选资源上标记冲突，不递归拉入其他任务的端点。所有当前任务的必要参数及资源承诺仍可见，等待和执行差距由程序评估。

全部授权舰队逐支保留稳定引用、归属、兵力、状态和目的地，不再把非相关舰队仅汇总成数量与兵力。已有来源、返航能力等授权字段继续提供；缺失字段保持未知，列表出现不代表空闲或安全可调，列表消失不推断抵达或毁灭。非相关己方据点的经济计算仍可按设施类型汇总，矿场与相关据点保留必要经济明细；每个可见据点的类型、兵力与护盾始终由默认目录提供。指挥官讨论和转译使用同样的默认核心事实；未处理聊天、确认正文、硬约束和真实回执保留。响应不再包含 `needsInformation`，模型不能请求补充资料后追加调用。

模型输入不携带 `global.planning` 的通用候选、评分、出兵来源、逐路线配兵、航程与来源预算。`attack-context.ts` 仅对本轮明确范围、触发、原文提及或确认指令所指向的目标生成 `attackAssessment`，保留评估时刻、目标、程序初筛结论与关键原因；任务身份触发关联其目标，普通任务存在和程序排名不自动展开候选。没有相关结论时不发送该字段。指挥官讨论按当前正文涉及的目标提供结论；明确提到对手时，最多提供该对手三个相关目标的结论。通过初筛、条件待满足、既有进攻需复核及窗口内无未占用来源分别表达，不表示前台已选方案、已执行或不可进攻。前台自主选取具体战术，模型只制定战略方向、资源边界和外交安排。

现有进攻任务的目标另在 `facts.taskTargets` 提供名称、归属、设施及当前兵力和护盾，不因此展开位置、生产或周边舰队。默认据点目录也保留相同核心事实。当前任务的必要参数、执行原因及执行差距继续提供，原始任务理由保留在程序笔记与审计；不通过额外模型调用回读。配置评估提供当前己方兵力；运输两端均已授权且 144 世界日运动搜索未抵达时，明确标记 `beyond-144-world-day-window` 与超出执行窗口。端点缺失和真正未知仍保持区分。

调用审计的 `contextSelection` 保存材料版本、展开实体与原因、汇总身份、确定去重项、按职责排除的字段路径与原因、数值展示调整、实际编码后各正文字符量及完整提示词长度；职责排除、逐值去重及精度调整分别记录。`modelReferences` 保存该请求的短代号映射。这些审计数据不发送给模型，不增加分段标记。完整具名简报仍用于发布依据、权限及外交事实校验。后台战略唤醒原因进入整轮 `changes.triggers`，与已有触发合并保留；初始、周期、威胁、重要状态和任务执行问题的唤醒不伪造具体变化实体，也不据此预拆独立模型任务。

进攻初筛、排序、分数、来源估算、投入缺口、路线及建议期限继续保留在程序完整简报与诊断中，执行和发布校验不使用精简模型视图。模型所需的现有任务执行差距在 `executionFeasibility` 独立保留，不再依赖被排除的候选还原；移除逐来源明细，仍保留投入上限是否不足、关键成本估算、期限是否足够和实际关联操作等程序反馈。模型不重新审批前台已经选择的行动，初筛结论不代替真实回执。

战术反馈的模型视图提供已选方案动作、按程序建议排序的替代方案相对动作增减、关联目标、命令数量、已有计算的投入缺口、条件结果、未知风险和复查条件。前台在保留原始评分审计的同时记录这些决策后果，以精确候选身份关联已选方案，不按可能重复的目标字符串猜测。模型视图不含内部 `utility`、权重分项、组合目标字符串、命令身份或搜索次数；只保留搜索完整性与停止原因。缺少具体动作或后果的历史记录只标为目标方向或未计算，不重构兵量和结论。反馈中的舰队引用使用现有稳定短代号；短代号冲突或与其他身份空间冲突时保留精确原编号，不猜测映射。此整理不改原始消息、回执、前台选择或内部审计，也不把条件方案写成已经执行的事实。

正式回执按职责与会话维护成功发布后的消费边界，不再每次固定重复最近十二条。失败、过时及取消的输出不推进边界，分段指挥官转译完成发布后才确认消费。每次仍给当前关系、义务及历史结果摘要，不假设模型自动记住上一份 JSON。回执来源为玩家当前授权观察窗口；窗口外未展开的事件数量和覆盖限制明确给出，不声称已逐条消费或还原全历史，不补造缺失事件。完整审计、控制器执行查账及未决写入继续保留。

固定模型 Schema 定义各职责的结构；动态权限清单与归一化、发布校验共享本轮职责边界：外交无已签合同不开放军事编辑；当前会话各合同明确列出可编辑任务身份、进攻目标和防守支持范围。独立战略、指挥官及其他会话或合同的任务作为无可编辑身份的只读背景保留，不进入外交任务更新和取消清单。履约评估只提示当前合同的可编辑任务；本方占领目标已完成或只有停战合同时，动态权限清单不提供 capture 许可，仍允许合法防守支持及取消本合同旧任务；固定 Schema 保留 capture 的结构定义。发布时依据最新授权观察和持久任务来源重新校验，不以生成侧约束替代权限检查。

任务更新只列合法身份和未来期限，所需来源、数量等字段按任务种类声明，夺取、配置和运输任务均要求显式数值优先级，避免在改目标或改类型时依赖无法安全继承的值。配置目标及指定运输的两端只提供当前己方据点；在途占领不能当作已归属。已知但与当前外交动作无关的字段只进入归一化审计，不改变执行动作。当前会话只有一份已签合同时由程序绑定履约来源；多份合同时显式选择精确身份。显式关联可从浅层任务项提升，所有关联必须一致，不能根据自然语言或目标推断，也不自动改写错误的显式身份。同一目标的不同合同任务分别保留来源，不能通过自动去重改绑。指挥官约束缺失、未知引用及真实语义冲突继续拒绝。
