# 持久化与数据隔离

## 数据位置

| 数据 | 默认位置 | 责任 |
| --- | --- | --- |
| 实验室活动对局 | `runtime/subterfuge.sqlite` | 权威状态、命令、事件及协议领域 |
| 玩家凭据 | `runtime/player-access.json` | 当前房间 owner 身份，私有文件 |
| 本机绑定 | `runtime/controller-bindings.json` | 游戏席位到固定控制器槽位 |
| 控制器状态交接 | `runtime/ai-controller-slots.json` | 本机状态摘要，不能代替真实租约 |
| 独立控制器私库 | `runtime/independent-agent/<绑定哈希>.sqlite` | 每席策略、笔记、日志、诊断和运输账本 |
| 槽位配置 | 控制器 store 的 `controller-slots.json` | 固定槽位模型和无密钥配置 |
| 多房间大厅 | `runtime-rooms/<房间码>/` | 每个房间的独立持久状态 |
| 本机联动存档 | `runtime/checkpoints/<存档编号>/` | 一致游戏/控制器阶段性快照 |

实际位置由启动参数和数据目录环境变量决定。运行目录不属于可随文档或代码整理删除的内容。

## 游戏 authority

RoomStore 使用 Node 内置 SQLite，WAL、完整同步、外键与事务校验。当前指针、快照摘要、追加命令与事件在同一事务提交；冲突或失败回滚，不公布未保存世界。加载严格校验格式、摘要和回放一致性；正常路径可复用已验证前缀，不跳过规则或历史校验。

协议宿主通过 `RoomStore.current()` 复用已完整校验的不可变当前切面；同一存储修订不重复复制全局历史。活动房间或修订变化、其他连接写入引起的 SQLite `data_version` 变化都会使缓存失效，重新检查快照摘要及追加日志。普通 `load()` 仍返回隔离的可变副本；显式校验和备份仍检查实际数据库，不以当前缓存代替审计。协议、聊天等同连接写入不会改变已验证的游戏切面。

缓存命中检查只读取轻量修订与 SQLite 数据版本，不为取得摘要反复查询含大存档的行。本进程每次状态写入都会使缓存失效，相关计数不随事务回滚回退，避免修订号重用时误认另一份状态。单局网页宿主只在切面变化时重新载入可变工作状态；独立游戏服务的时钟检查使用不可变切面，不为每次脉冲复制整局。授权、控制权和协议账本仍按各自事务读取。

多房间大厅通过 `LobbyStore.current()` 共享已验证的不可变大厅、开局和运行切面；修订、本连接状态写入或外部连接的数据版本变化都会使当前切面失效。未改变的开局和等待世界可复用已验证结果；运行态仅时钟元数据变化且房间正文相同时，共享同一已验证房间。本连接产生的后续局面可从已验证的命令前缀继续回放，并与完整保存状态比较。首次加载、外部连接写入后的运行态及显式 `verify()` 使用完整回放；可变 `load()` 保持副本隔离及事件时授权事实关联。没有新的整秒时钟边界时，不重复序列化和保存运行态。

协议账本保留所有命令和回执，未决检查通过仅含 `accepted` 的索引读取；终态自动离开该索引。事件按房间、席位与规范序号长度／序号的复合索引定位游标后的新增段，空读取不扫描全部旧事件。索引不改变幂等、租约、回执和查账语义。

聊天、Commander、控制与协议账本经宿主绑定到同一 authority 连接，业务效果、最终回执及过滤事件按协议边界共同提交。仅复制数据库不能证明包含外部凭据、控制器历史或交接配置。

便携 JSON 导入/导出是局面接口，不是完整联动备份；便携大小和数量限制与可信本地 SQLite 路径分别校验。不能在请求里填写 trustedLocalStorage 绕过限制。

## 控制器私库

| 表 | 用途 |
| --- | --- |
| seats | 当前席位私有状态、设置与游标 |
| journal | 追加事件、工具/执行依据及审计 |
| runtime_state | 程序恢复所需当前运行投影 |
| diagnostic_calls | 模型/讨论调用的计量、状态及结果摘要 |
| diagnostic_call_index、diagnostic_call_heads | 调用版本、正文保留状态与每次调用最新位置的派生索引 |
| player_protocol_client | SDK scope、游标、会话与当前核心状态 |
| player_protocol_outbox | 按键独立保存命令 intent、状态与回执 |
| player_protocol_delegation | owner 引导的独立 executor 授权记录 |
| player_protocol_revision | 协议核心与命令表的事务内修订计数 |
| journal_rewrite_revision | 笔记、提醒及复核历史被改写或删除时的修订计数 |

核心协议文档使用 `outboxStorage: "sqlite-outbox/1"` 并保持内嵌 outbox 为空；完整记录在 outbox 表，二者在同一事务维护。诊断和恢复必须使用适配器或按契约合并读取，不能把内嵌空对象解释为没有未决操作。

当前协议状态读取延迟展开历史命令；SDK 单条命令按键查询，未决及预约命令按索引查询。协议编码缓存只在相关表修订后失效，不因日志追加反复载入；事务只解析和更新实际访问的命令，显式历史读取仍返回隔离的完整副本。笔记与提醒按事件游标增量投影，追加事件不会清空投影；相关历史被改写、删除或回退时由事务内修订重新构建，保留跨连接和编号复用的正确性。

请求、轮询及就绪耗时属于性能采样，统一在内存缓冲，每 500 毫秒合并为一次日志事务，正常关闭时刷新剩余采样，不读写席位决策状态。存档冻结前排空缓冲，冻结期间停止请求采样。异常退出可能丢失尚未落盘的性能采样；命令意图、操作回执、事实确认和恢复依据仍在各自操作边界完整持久化。

策略的 `state`、`search`、`decision`、`feedback`，以及 `attack-screening`、`decision-observation` 和 `round-workset` 的完整正文只在 `runtime_state` 中覆盖保存最新一份，用于当前展示和重启恢复。每次更新仍在 journal 保留种类、轮次、正文大小及 SHA-256 的 `diagnostic-snapshot-summary/1` 摘要，不把摘要当成可还原的历史正文。当前状态和摘要在同一事务提交，失败一起回滚。

操作集合历史承担未提交操作的查账依据，继续完整保存；相同操作快照可用 `snapshot-repeated` 引用直接指向先前正文。命令意图、操作与协议回执、实际执行依据、观察基线、私有笔记、指挥官记录和未识别扩展事件继续按原契约持久化，不按诊断名称批量删除。

模型与指挥官调用按房间和席位合并保留最近 20 次调用的上下文、响应 Schema、请求参数及模型回复正文；超过窗口后压缩为摘要，`rawOutput` 等运输层正文一并剔除。调用摘要保留模型、状态、时限、排队与执行耗时、Token、上下文字符数与指纹、结果摘要、失败信息，以及材料选择和引用映射等校验审计。原始模型结果仍在当轮内完成业务校验，实际发布内容与执行回执另行持久化；窗口外调用的诊断读取明确返回 `summary-only`，不把未保存正文误报为捕获失败或未调用。当前席位行内容未变时不重复更新，CAS、审计顺序和恢复边界保留。

调用保留范围通过小型派生索引维护。首次建立索引时读取现有调用记录；后续插入、更新和删除由同事务触发器同步维护每次调用的最新位置及尚有正文的记录。清理只查询最近调用位置和刚移出窗口的正文，不重复解析已压缩历史；回滚同时恢复正文和索引，保留原有最近 20 次调用的边界。

数据库按服务器 origin、roomId、lobbySeat 与实战标记确定绑定，内部再次核验。新局不混入旧局笔记；固定槽位配置复用不等于私有历史复用。不能改 scope 或搬旧 outbox 来恢复新 epoch。

## 备份与恢复

只需游戏数据库时，构建后可用：

```powershell
npm run storage -- verify /path/to/subterfuge.sqlite
npm run storage -- backup /path/to/subterfuge.sqlite /existing/backup/new.sqlite
npm run storage -- restore /existing/backup/new.sqlite /existing/restore/new.sqlite
```

目标文件必须不存在。数据库备份使用 SQLite 一致备份路径并校验，不是热复制主文件；恢复只写新路径，不覆盖运行服务。需要本机完整对局和 AI 连续性时使用[联动存档](linked-checkpoints.md)，独立服务 clone 规则见[游戏服务](game-only-server.md)。

## 容量与清理

减少重复状态写入与减少保留历史是不同操作。分离 outbox 避免每次重写全部命令历史，但不承诺数据库不会增长。SQLite 文件大小、WAL、有效页、诊断日志及备份分别统计；删除记录不等于文件立即缩小。

未决命令、授权、游标、恢复依据和实际结算不能作为普通诊断缓存清理。当前没有“每 20 tick 才持久化”的通用策略；持久命令与事实仍按事务保存。

只在明确范围和授权下清理数据；正常对局不主动重建。失效开发存档严格拒绝，不为其增加自动补字段或迁移分支，处理约定见 [AGENTS.md](../../AGENTS.md)。
