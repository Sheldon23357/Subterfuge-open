# Gemini 结构化输出规范

本文约定 Gemini 模型输出 Schema 的设计、校验与兼容性验收方法。连接配置见[运行说明](ai-runtime.md)，模型职责与授权边界见[上下文规范](ai-context-refactor.md)。具体模型字段仍以源码为准，不在本文维护另一份任务协议。

## 当前实现与边界

原生适配器 [`gemini.ts`](../../packages/ai/src/application/providers/gemini.ts) 使用 `models.generateContent`，在 `generationConfig` 中同时传入 `responseMimeType: "application/json"` 与 `responseJsonSchema`。只要求模型输出 JSON、只设置 MIME 类型或调高思考等级，都不能代替 Schema 配置。Interactions API 使用自己的请求结构，不能直接混用参数。

hybrid 的 [`model-wire.ts`](../../plugins/hybrid/src/model-wire.ts) 按职责和服务器合同协议能力生成固定浅层模型结构；合法对象、任务和合同范围在动态 `facts.permissions` 中给出，不进入生成 Schema。输出依次经过 JSON 解析、确定性转换、名称解析、语义与权限校验，发布前还需复核材料依据。Schema 被供应商接受不代表任务合法，更不代表指令已执行。

[`gemini-schema.ts`](../../packages/ai/src/application/providers/gemini-schema.ts) 为 Gemini 生成独立投影：保留 JSON 类型、必填字段、完整任务动作分支及固定动作分类，可把输入 Schema 中的引用枚举、数量和数值边界等从解码语法移到同源描述中。hybrid 的生成 Schema 已不含动态对象枚举，权限清单随正文提供；原 Schema 不被修改，内部容量、捕获权限与最新发布守卫继续执行。完整对象分支不重复展开公共字段，避免叠加两份可选字段语法。

hybrid 通用输出始终包含 `summary`、`tasks`、`cancel`、`reviewOn`；无内容时返回空字符串或空数组。任务按动作使用完整结构，返航填写 `fleetId`，不以据点 `target` 代替。缺省兼容与审计仍由现有解码流程负责，不从 prose 猜测目标、兵量或合同身份。

## 官方能力与校验分工

Gemini 支持 JSON Schema 的部分能力，包括基础类型、对象字段、必填字段、枚举及部分数值和数组约束；可空值使用明确的类型联合。官方说明字符串长度、对象字段数量、数组唯一性等部分约束不会由解码器执行，应用端必须检查。较复杂的 Schema 可能返回 `400 INVALID_ARGUMENT`。具体支持范围以 [Google 结构化输出文档](https://ai.google.dev/gemini-api/docs/structured-output)和 [GenerateContent 参数定义](https://ai.google.dev/api/generate-content#v1beta.GenerationConfig)为准。

## 项目设计原则

以下约定同时用于生成投影、原始任务契约和后续修改；生成侧描述不是服务器权限或本地校验的替代品。

1. **保持职责单一和结构浅。** 分别生成战略、指挥官与外交所需结构，避免把内部执行器、完整存储对象或无关职责拼成一个大型联合类型。扁平化后仍要控制字段总量与可选字段组合。
2. **固定分类用小枚举。** 动作种类、状态等稳定分类可使用 `enum`。地图名称、舰队和任务 ID 等动态集合优先由授权材料提供，并在程序中精确核验；不能默认把完整集合重复展开到每个字段都可被供应商接受。
3. **简化传输约束时保留语义。** 从供应商 Schema 移除动态枚举，只能减少生成侧约束，不能扩大实际允许的名称或权限。不得截取前几个名称作为正式候选，造成合法目标无声消失。任何投影必须确定性生成，原内部约束继续执行。
4. **数组上限按职责与内容设计。** `maxItems` 是生成约束，也可能增加 Schema 编译复杂度，嵌套对象数组需特别验证。不能为通过接口就随意降低任务或外交容量；确需缩小输出容量时，先明确任务完整性与超限处理，应用端仍保留数量检查。
5. **控制分支与可选字段。** 多个长枚举、大量连续可选字段、较多 `anyOf` 分支和数值上下界需要组合测试。单字段通过不代表组合通过。必填、缺省、`null`、零和空数组各有含义，不得通过强制全部必填或自动补零来消除分支。
6. **校验类型相关参数。** 浅层任务仍须检查动作所需字段、字段适用范围、正整数兵量、期限、来源和目标关系。已知但不适用于所选外交动作的字段，由解码器按现有规则忽略并审计，不能解释为新动作；合同身份冲突、未知引用、缺失关键参数及其他无效结果仍拒绝。移除供应商侧约束不能替代这些检查；无效响应不得发布为指导或进入游戏写入。
7. **提示与结构共享来源。** Schema、示例及转换规则从当前定义生成，提示词只解释含义和取舍，不另写一份易过期的字段协议。不要依赖 `reason` 或 `summary` 承载实际执行参数。

## 兼容边界的判定

兼容性必须按模型 ID、接口、Schema 版本和实际字段组合确认，不能定义未经验证的全局“枚举最多几项”或“数组最多几项”。相同字段数量下，名称长度、可选性、嵌套、分支和其他约束不同，都可能改变结果。通用 `INVALID_ARGUMENT` 也不足以单独证明具体后端复杂度上限。

采用对照测试定位拒绝：固定模型、接口和提示词，先比较完整 Schema 与最小类型结构；再按顶层字段、任务字段组、枚举数量、数组上限逐层拆分。每轮只改变一个明确维度。找到通过与失败的区间后测试相邻值，并独立复测临界两侧；网络错误、429、超时或输出截断应单列，不当作 Schema 编译失败。

诊断中的枚举裁剪、约束删除和容量降低只用于辨认影响因素。实测通过的简化结构必须再经过语义保持审查，才能作为生产适配方案。

## 验收要求

- 分别覆盖战略、指挥官和外交；覆盖空及非空任务、无及有既有任务 ID、舰队引用、不同外交动作和指挥官约束。
- 覆盖小规模及实际规模的授权名称集合、多个枚举同时出现、数组最大容量和主要可选字段组合。最小空对象或空数组成功，只证明该请求被接受。
- 验证非空输出可以经过模型结构转换及内部严格校验；再用隔离对局确认指导发布、前台处理和实际回执。HTTP 200、JSON 可解析、语义有效与执行成功分别记录。
- 模拟供应商测试验证参数、解析、取消和错误处理；真实供应商测试验证实际模型的 Schema 接受能力，两者不能互相替代。
- 记录源码版本、模型与接口、Schema 原文或哈希、变更维度、HTTP 状态、输出校验结果及未知项。具体请求和边界数字存入本地 `runtime/` 或 `outputs/`，不将某次探测值写成永久产品保证；记录不得包含 API key。

遇到稳定的 400 时保留脱敏诊断，先通过最小复现确定参数问题。不得通过无限重试、提高 Token 上限、关闭 Schema 或放松内部权限校验来掩盖不兼容。

## 执行真实模型检查

设置 `GEMINI_API_KEY` 或 `GOOGLE_API_KEY` 后，在项目根目录运行 `npm run test:gemini`。这是显式调用真实供应商的检查，会消耗模型额度；不会随 `npm test` 自动执行，不连接游戏或提交玩家操作。需要代理时沿用运行说明配置的进程代理环境。

检查通过当前原生适配器发送源码生成的完整模型结构，覆盖后台战略、指挥官转译、外交，讨论、提案确认和默认工具信封；同时覆盖非空任务、返航、合同回应、反提和履约。固定生成结构不嵌入运行时对象枚举；合成案例正文提供完整授权名称，容量案例验证内部任务与复查条件的原定上限。实际权限的正反例、发布新鲜度、固定 Schema 与提示词指纹稳定性另由本地回归覆盖，供应商转录检查不替代权限与实际对局验证。

可通过 `npm run test:gemini -- --out runtime/my-gemini-check` 指定报告目录，或在参数中指定脚本声明的案例名进行局部检查；未知案例名报错。默认模型取 `GEMINI_MODEL`，未配置时与适配器默认模型一致。输出必须通过相应解码与解析，关键动作、引用、数量和数组内容与合成案例核对，说明文字允许改写。通过有限案例不保证模型每次遵从要求，也不代替实际对局和执行回执验收。
