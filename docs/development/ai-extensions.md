# AI 本地插件与源码扩展

AI 控制台由共用宿主与策略插件组成。默认提供完整源码的官方 hybrid 插件，通过同一目录加载器安装；本机控制台可扫描本地目录并编译加载可信 TypeScript 插件，每个席位独立选择。插件与宿主同进程运行，不是安全沙箱，不支持 Python、远程插件 URL 或跨版本二进制 ABI。游戏连接、模型准入、执行校验、回执、存储与暂停恢复由宿主统一维护。

## 本地插件文件夹

每个插件放在独立文件夹，包含 `bot-plugin.json` 和入口源码。可复制仓库的 `examples/bot-plugins/hybrid-copy/` 作为完整 hybrid 模板：

```text
bot-plugins/
  my-hybrid/
    bot-plugin.json
    index.ts
```

清单示例（准确校验以 `application/plugin-catalog.ts` 为准）：

```json
{"apiVersion":1,"id":"my-hybrid","name":"我的 hybrid","version":"1.0.0","entry":"index.ts"}
```

入口默认导出 `BotModeDefinition`，可使用公共类型自行实现，也可复用官方组件：

```ts
import {defineHybridMode} from '@subterfuge/hybrid';
export default defineHybridMode({id:'my-hybrid'}, '我的 hybrid');
```

清单 ID 必须与导出定义一致，`hybrid` 是随包官方插件使用的默认标识；同 ID 不能同时加载两个插件。API 版本目前为 1，插件版本采用三段数字。入口为目录内的相对 TypeScript 或 JavaScript 文件。完整官方实现位于 `plugins/hybrid/src/`，其中战略、外交、提示词、发布、约束与前台协同均可编辑；模板不是宿主内置实现的唯一包装层。相对依赖随入口打包，公共宿主入口使用运行器当前版本；插件不能依赖 `/runtime` 或内部包路径。这里的导入约束帮助维护接口，不构成权限隔离。编译只转译 TypeScript，不代替插件开发者自己的类型检查。

在暂停席位的配置中点击“扫描插件目录”，填写本机绝对目录，可选插件目录本身或包含多个插件文件夹的目录。扫描只读清单；信任后加载才执行代码。选择后返回席位配置；仅当插件要求参数时展开“插件参数”填写 JSON，不需要时留空，保存时再次校验，其他席位不受影响。已加载插件也可从 AI 实现列表直接选择。

基本校验检查配置接口、所需钩子、能力与记录命名空间、独立实例工厂，以及已绑定席位的只读玩家协议身份连接。未绑定时明确标为连接待检查。校验不下游戏指令，也不证明策略强度、所有可选钩子语义或长期稳定性。

仓库安装依赖后具备编译器。独立分发包和玩家开发包自带本平台 esbuild、TypeScript 与完整 SDK，不需要安装 npm 编译依赖；运行与离线检查命令见[宿主与插件分发](bot-distribution.md)。

运行器将编译快照与摘要保存在运行目录的 `plugins/<id>/`。源文件改动不自动生效；同 ID 更新要求先把所有使用它的席位切换到其他插件，再显式重新编译更新。失败保留已加载版本，重启读取快照并校验摘要；缺失或损坏时保留选择以供诊断，拒绝启动，不自动换成 hybrid。恢复源目录后重新加载，或显式选择其他插件。游戏中的未决写入仍须先按原身份查账，不能用切换插件绕过。


## 运行示例

在仓库根目录、已安装项目依赖的 Node 环境中执行：

```sh
npm run ai:example
```

该命令构建真实控制台，使用独立临时网页目录和私有运行目录，打印随机回环端口地址。初始预置八个未绑定槽位，没有游戏连接，所有新接入席位保持暂停；不会读取本机游戏绑定。可在控制台显式连接游戏、选择 AI 实现并启动。

已有真实连接配置可显式指定：

```sh
npm run ai:example -- --config /path/to/my-seats.json --port 4400
```

连接配置沿用[运行说明](ai-runtime.md)的结构和凭据环境变量；可复制 `examples/ai-extension/config.example.json` 并填写自己的游戏连接。策略标识放在席位的 `settings.mode`；该示例的模型名称仅是本地测试标识。指定配置文件后，网页不提供本机发现或修改连接。示例模型来自 `examples/ai-extension/model.ts`，只生成确定性 JSON，不访问供应商，也不声称具备战略能力。真实模型需在自己的启动组装中明确注入，或在控制台配置供应商。

## 公共入口与注册

| 入口 | 使用者与能力 |
| --- | --- |
| `packages/bot-sdk/src/index.ts` | 插件公共策略契约、授权输入类型及轮次上下文构建 |
| `packages/ai/src/runtime.ts` | 启动文件组装运行器、配置和本地控制台 |
| `plugins/hybrid/src/api.ts` | 官方 hybrid 工厂、提示词、简报与规划组件 |
| `packages/ai/src/providers.ts` | 模型传输实现及环境供应商组装 |

独立插件使用 `@subterfuge/bot-sdk` 及其声明的子入口，官方策略 API 使用 `@subterfuge/hybrid`；宿主运行器与供应商入口用于仓库启动组装，不是插件的私有控制通道。仓库里的内部集成入口 `src/index.ts` 不属于玩家扩展入口。示例的策略文件只依赖公开策略入口与公共 contracts，不深层导入控制器或数据库实现。

`BotModeDefinition` 声明标识、显示名称、模型/指挥官能力、配置校验和实例工厂。启动文件将定义交给 `BotModeRegistry`，再将注册器注入 `AgentRuntime` 的 `modes` 选项。首次创建 resolver 后源码注册封闭；本机目录由宿主受控安装新定义，更新须先解除席位选择。未知策略、重复标识、错误命名空间、能力不一致及跨席位复用同一实例均拒绝。

`settings.strategyConfig` 是策略自己的配置，由定义的 `validateConfig` 严格校验，并以独立副本交给 `create`。同一席位相同策略和配置复用实例；改变策略或配置创建新实例。公共设置继续由宿主校验，策略不能借配置修改游戏协议或授权范围。

## 一轮决策与组件替换

`prepare` 接收整轮触发原因、授权观察、实际反馈及策略自己的私有记录，返回本轮上下文与 `run`。策略可返回 `order`、`batch`、`say`、`notebook`、`reminders` 或 `finish` 建议；宿主统一校验并执行。行动建议中的据点参数使用授权完整名称，程序可从观察的 `outpostNames` 将稳定身份映射为名称；舰队仍使用其精确身份。模型返回的 JSON 不是执行许可，策略必须先按自己的输出契约解释。

本地计算通过 `services.local` 进入宿主的暂停与检查点准入；模型调用通过 `services.model.step` 共用队列、取消、限流、时限和审计。真实业务调用应显式提供 `responseSchema`；省略时传输默认只要求空 JSON 对象。`ModelResult.reply` 是未经业务解释的 JSON，`AgentResult.reply` 才是提交给执行器的行动建议。本地计算不属于模型传输接口，不累计虚构的模型用量。

`afterAction` 负责一条行动或批次完成后的确定性记账与收尾；官方 hybrid 在此结束本轮，后续行动等待下一轮触发。后台通过 `createBackground` 取得受控模型和策略记录服务，管理暂停与排空；发布前必须复核授权事实、指挥官和任务依据。后台不直接调用游戏写入。

`onReceipt` 在实际执行回执持久保存后同步更新模式的本地投影，不等待后续战术轮次。它提供本次请求身份、按原始尝试查询回执、读取及保存模式记录和登记后续唤醒；不提供模型、搜索或远程写入。只能使用本次身份匹配的账本证据确认结果，未知不能当作未执行；完整撤军批次确认前不能签署。回执原文和系统观察游标先持久保存，本地投影可在重启后由原账本恢复。

`createHybridMode`/`defineHybridMode` 支持注入 `briefPrompt`、`commanderPrompt`、`buildBrief`、`planner` 和 `localPlanner`。未提供的组件使用官方实现；发布校验、外交权限、实际回执和执行前守卫仍由官方流程维护。修改材料构建时仍须遵守[模型上下文规范](ai-context-refactor.md)，不能扩大玩家视野或把条件预测写成事实。

`examples/ai-extension/strategies.ts` 提供工厂程序策略及替换提示词、规划组件的 hybrid。程序策略只是最小执行示例，不是强度建议；策略可以完全改成模型主导，而继续复用宿主执行基础。

## 状态、诊断与切换

策略记录通过 `latest`、`record` 访问，宿主固定添加 `mode-<策略标识>-` 前缀，并按服务器、房间和玩家隔离。普通策略记录不能冒充公共命令回执或修改已确认指挥官指令。公共笔记、事实和执行账本由宿主独立维护；历史日志不提供给模型作为 recall。

策略可提供 `diagnostics` 投影；`strategyDetails` 在控制台按只读 JSON 显示。通用运行状态、命令回执、调用用量和错误仍由宿主提供。宿主自动记录后台模型调用的准入、实际输出、用量和取消；策略可用调用身份关联更具体的业务校验结果。后台调用事件采用统一的 `model-call`、`task-dispatched`、`task-failed`、`task-skipped` 和 `usage` 名称，宿主在查询时绑定当前策略命名空间。

切换策略或配置前必须暂停，等待前后台、指挥官、租约和检查点收尾。存在未决写入或未完成的指挥官清理时拒绝切换，先按原请求查账；不能换策略绕过恢复。新策略不支持已有已确认要求时拒绝切换。切换保留各策略的私有记录并安排重新评估，重新启动需要显式操作。

扩展代码与宿主在同一进程运行，接口边界不是代码安全沙箱。核心执行守卫及服务端授权仍是游戏操作的共同约束。
