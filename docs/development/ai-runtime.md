# bot 控制台与运行

## 责任

游戏服务器负责真实状态与结算。独立控制器通过玩家协议读取授权观察、聊天、通知、实际事实和回执；模型、私有笔记、策略与用量保存在控制器本地。预测和候选分析由本地共享库完成，不读取游戏数据库或管理员全图。

控制器只提供[分层协同](hybrid-bot-guide.md)：后台模型负责战略与外交，前台负责本地战术搜索；模型连接可选“不配置模型 · 自主决策”。公共接口见[模式架构](controller-bot-modes.md)。

## 本机控制台

```powershell
npm run ai:dev -- --console 4400 --store-directory runtime/independent-agent --local-game-directory runtime --local-player-port 4311
```

打开 http://127.0.0.1:4400 。控制台仅监听回环，使用本进程会话和 CSRF 校验，不是多用户密钥管理服务。

会话 Cookie 名按控制台端口固定，重启覆盖原值；会话与 CSRF 随进程重新生成，旧值仍失效。主页会清理本控制台早期随机名称的 Cookie，保留其他应用和其他端口的固定会话。游戏网页和控制台采用 64 KiB 的有限请求头上限，允许清理已累积的旧 Cookie，避免跨端口共享 Cookie 导致 HTTP 431。

Tick 计时统一读取绑定服务器的 `tick-times.read/1` 协议接口，云端与本机连接采用同一路径；控制台不打开游戏数据库或使用本机数据库的时间记录。服务器在实际 tick 提交事务中记录边界，返回当前 tick 已过时间；网页只用本机单调时钟平滑显示服务器样本，不用电脑墙钟推算。缺失历史标为起点不完整，离线批量推进不插值拆分，跨进程间隔包含停机时间，终局停止计时。 关联大厅的控制台在开局前显示服务器确认的等待状态及开局倒计时；本机仅平滑显示剩余秒数，归零后等待服务器确认，再切换为 tick 计时。未提供该接口的服务器明确显示不可用，不回退到本机文件。

固定槽位为 AI 01–08。先启动本地控制器（`http://127.0.0.1:4400`），再从大厅加入游戏房间。在房间自己的席位或等待中的空位点击“绑定 bot”，浏览器打开控制器页面并弹出槽位选择；选择未绑定槽位，可展开模型设置，确认后完成绑定。不能接管其他玩家席位。连接后保持暂停，由用户手动启动；未绑定槽位可配置，但不能启动。

取消弹窗不领取空位。确认时由房间网页领取所点的确切空位；席位被占用、房间已开始或已关闭时拒绝，不自动换位。重试复用同一领取凭据。控制器再次通过玩家协议核验房间及席位身份，再绑定选定槽位；已有绑定不会被覆盖。若领取成功后本机连接失败，已领取的席位保留，可重试完成绑定。

窗口交接核对来源、窗口引用及随机关联号；玩家凭据只通过窗口消息和本机同源 API 请求体传递，不进入网址、公共状态或日志。本机 API 继续要求会话 Cookie 与 CSRF 校验。房间窗口须在确认前保持打开，关联窗口五分钟后失效；控制器未启动时应先启动并从房间重试。控制台的“连接游戏”按钮直接在新标签页打开大厅，不显示中间引导弹窗；加入房间后从席位发起绑定。

首次从控制台打开游戏时，默认使用本机大厅 `http://127.0.0.1:4312`。使用自托管大厅时，从该大厅的“AI 控制台”入口打开，本机控制台会沿用该大厅地址。

公网执行连接使用可信 HTTPS；已有 HTTP 大厅仍可在原来源读取已保存身份，控制台后端将公网连接升级为同主机的 HTTPS，不关闭证书校验。不同浏览器或清除站点数据后无法自动识别原网页身份。

浏览器身份互不共享。在另一浏览器打开同一个本机控制台后，可选择已经连接的大厅席位，点击顶部“打开玩家页面”恢复该席位。该入口只交付已有原玩家身份，不将执行器授权转换为玩家身份；请求受本机会话与 CSRF 校验保护，窗口消息核对来源、弹窗及一次性 nonce，凭据不进入网址、公共状态或日志，接收页先向服务器核验身份再保存。

同一个控制台可以绑定多个不同席位；玩家可以依次点击房间空位，为同一房间的多个空位选择不同 bot 槽位。每个 bot 独立选择席位、模型和启动状态；已绑定席位不被后续连接覆盖。

连接后，大厅席位显示 bot 名称和配置的模型名称，控制台顶部已绑定 bot 同步显示模型名称。未配置模型时显示“自主决策”，模型名称不代表已发生模型调用。该连接标记表示本机控制台的绑定连接，不代表模型已经启动或正在思考。控制台每 10 秒向大厅续报连接及当前模型名称；断开时撤下标记，失联记录最多保留 30 秒。已被另一有效连接占用的席位拒绝覆盖，玩家手动控制、独占租约和执行器权限仍按原协议校验。配置文件模式继续由配置文件管理，不开放网页更改绑定。

控制台默认打开「实时运转」，各页签共用深蓝仪表盘配色、全部 bot 席位切换和标签栏右侧的检测、连接、启动／暂停操作，不另显示席位、模型与房间信息顶行或席位侧栏。日志、笔记、评估、统计与配置使用统一面板、表单、表格与工具栏。实时页按可用窗口宽高伸展，页面不出现横向或纵向滚动条；较长的执行记录和开始页内容在模块内部滚动。

八个 bot 入口在桌面端等宽铺满可用宽度，窄屏为两行四列。未绑定游戏的席位显示带深海指挥舱背景的连接开始页，集中提供连接与配置入口，下方简要说明选择席位、配置决策、手动启动三步，以及连接后暂停、模型可选和运行器需持续开启的规则；已绑定且授权诊断确认尚无运行记录的暂停席位显示启动开始页，提供配置与启动入口。读取中不推断为未运行；已有实际轮次、方案或执行记录的暂停席位继续保留实时仪表盘，无模型调用不代表从未运行。开始页的连接和启动仍受原有连接模式及席位权限限制。

实时仪表盘顶部显示全部 bot 状态与细长运行链路，中部并排显示 AI 指导轨道、协议与约束蜂窝、候选搜索网络和具体指令，底部集中显示计算指标及预算。详细说明通过图形悬停提示查看，完整日志保留在日志页签。正在流转的链路使用光束、发光拖尾、到达波纹及模块边缘特效条，动效跟随实际运行状态。协议蜂窝读取服务器正式合同，待签署与履约中分别标示；与指挥官等来源的内部意图分开，聊天发送不冒充签署。协议蜂窝的图标与描边按约定或意图类型固定配色，角标独立表示处理、完成或异常状态；终止项变暗，禁攻约定本身不作为异常。

搜索数量是实际提交的条件模拟，评分和候选路线属于有限条件计算，不能视为战果或全局最优。网络展示最近最多 40 条可用候选，执行指令显示动作名称、完整来源与目标、兵力、舰队或护盾开关参数，并逐条显示独立回执；未记录的回执不沿用整组状态。执行记录统一读取原始指令、批次子项回执和后续查账结果，覆盖自主决策与模型指导两条路径，展示最近五轮含行动的记录；空闲轮不挤掉已有行动，未知与未执行分别保留，已接受不代表已抵达或已获胜。当前方案与执行记录可分别切换，维持行动时明确没有新增操作。当前轮搜索期间保留上次方案，并标明所属轮次与观察是否过时。

运行状态和所选席位诊断在前台可见时约每 500 毫秒刷新；SVG/CSS 动画独立连续绘制，帧率显示来自浏览器实际绘制回调。具体执行明细读取既有授权笔记诊断，运行时约每 1.5 秒更新，暂停时读取一次；与主图同样遵守绑定世代和页面可见性边界。搜索进度以不超过每 100 毫秒一次的样本跨工作线程传递，仅驻留内存，不改动存档、私有状态依据、回执或审计日志。离开页面会取消所选席位的诊断请求，页面隐藏时暂停其查询；暂停、异常或连接中断停止相应运行动画。未记录与零分别显示。动画遵守系统减少动态效果设置。

日志、笔记、攻防评估、统计与配置保留各自页签，详细诊断通过刷新按钮手动更新。日志采用左侧调用列表、右侧详情的布局，两侧独立滚动；默认展开当前页最新调用，刷新时保留仍在当前页的选择，窄屏上下排列。日志与统计分别记录前台、后台和指挥官调用；无模型时保留本地战术搜索诊断，配置模型后可查看战略目标、后台任务和外交。每个 bot 按房间与席位隔离，合并自动决策、后台和指挥官调用，持久保存最近 20 次调用的上下文、回复与请求参数，重启后仍可查看；更早调用只保留状态、用量、耗时、上下文字符数与结果摘要。日志详情提供上下文、回复和请求参数切换、搜索及复制；超出保留窗口的正文显示仅保留摘要。已有记录若含完整正文，可按生成端分段标记展示为可折叠模块，支持结构化字段、表格、搜索和原文核对；未记录正文不从摘要重建。当前策略、搜索和决策显示最新完整快照，历史保存摘要及指纹；命令、实际回执、必要执行依据及笔记按[持久化约定](persistence.md#控制器私库)保留。

统计页将每 tick 耗时折线图与最近 AI 调用分析左右并排展示，窄屏上下排列。调用分析按本席位日志顺序合并自动决策（含后台模型）与指挥官调用，保留最近 50 次，在同一张双坐标轴折线图中展示上下文字符数（左轴）与总耗时（右轴）。曲线穿过实际样本，不跨缺失值连线；悬停或键盘左右键查看单次记录，批量推进等 tick 非完整记录另用点标记区分。逐次明细保留输入 Token、模型耗时、排队耗时及调用状态；总耗时使用调用记录值，不从 Token 数或图形推算。该板块只读取调用摘要，不下载上下文正文，随统计页刷新按钮更新。

攻防评估采用左侧攻击初筛、右侧己方防守压力的双栏布局，两侧独立滚动，较宽的表格在面板内横向滚动；窄屏按攻击、防守的顺序上下排列。评分依据、未知项与明细保持各自的观察时点和有效性标识。

笔记页按跨轮判断、执行承接、外交记录和程序记忆组织。左侧只保留竖向分类导航，右侧用两列深色卡片展开该类别全部已载入正文，窄屏改为单列，无须逐条选择。搜索与补充笔记类型筛选位于右侧，笔记正文支持逐卡复制。战略与指挥官指令分别呈现；作战意图展开当前任务、程序汇总约束、来源、期限及原因与执行反馈，排除已结束和已过期任务，无当前观察时保留待核实状态。外交协议只按服务器授权数据展示待签提案与履约中合同，展开停战范围、共同目标、双方额度、实际进度、期限和补贴，明确区分待签与已生效；外交判断读取当前保存的 `conversations` 会话摘要与内部意图，与尚存的独立协议判断按会话身份合并，不借用旧协议的状态或日期标记新的会话判断，也不以谈判笔记代替正式协议。复查事项展示战略的 `reviewOn` 条件及独立定时提醒，二者分别标明来源；条件本身不是定时调度，也不证明相关事件已发生。当前计算过程、任务调度及逐轮调用摘要留在对应页面；影响跨轮承接的结果与回执在笔记页展开。补充笔记仅统计通用笔记存储中有效的额外正文，战略、外交判断及作战意图保存在各自的数据中，不重复计入；当前模型响应不自动生成通用补充笔记。程序保存的行动计划归入存储详情，顶部笔记存储容量包含这类程序记录。有效期与归档按诊断结果展示，不通过正文推测当前事实。

行动与结果展开保留的未完成行动、关联意图、命令状态、近期结束任务和行动、上轮条件推演反馈，以及待查账请求和待交付的程序核实回执；命令接受、在途与实际结算分别显示。外交往来展示保留的会话原文、处理标记、发言发送状态、履约衔接和正式协议提交回执。协议结算与关系展示授权窗口内的已结束协议、结算回执和双向关系，回执窗口外的历史不推定不存在。指挥官讨论读取已安装的授权快照，展开讨论、完整提案和确认状态；讨论提案不能充当已确认指令。程序记忆与存储展开行动计划中的目标、已接受侦察目标与独立复核、人工操作及未确认事实、采矿阶段里程碑和上下文衔接记录。模型判断、条件估算、程序事实和内部衔接状态分别注明来源；部分记录可能供后续评审使用，具体入模仍由职责、会话、有效期和容量确定，页面不宣称所有已保存记录每轮都会完整发送。

笔记与提醒独立分批读取，旧记录追加为正文卡片，不替换已显示内容；搜索和笔记分类计数仅覆盖已载入记录，尚有旧记录时在右侧提供继续载入。行动分类计数为未完成行动数，协议结算分类计数为当前保留的已结束协议数。有效笔记总容量由程序另行提供，不以当前列表条数代替。稀疏历史扫描中的空页会在单批最多八次查询内继续查找；达到上限仍保留下一页入口。刷新重新读取首批及当前诊断快照；分页保留首批跨轮资料，切换席位取消旧查询。只读诊断从当前席位的已有数据库与授权快照读取指挥官、人工操作、程序计划和查账资料，不发起模型请求、服务器查询、证据确认或游戏操作。原始数据与底层审计保留，界面整理不会修改笔记、提醒或对局状态。

固定槽位保存模型、风格、战术参数与无密钥供应方配置，会话 API key 只留内存。配置在浮窗中编辑，由右上角“配置”或“配置席位”打开，关闭后保留原页签；运行中仍须暂停后才能修改。配置分为模型连接、策略参数和游戏连接，不提供策略模式选择。网页决策风格提供温和阴谋家、离间操盘手、闪击进攻、现实商人和外交协调五项，按纵向单列展示；已有其他保存值仍明确显示，只有选择并保存后才变更。暂停后保存配置，启动仅作用于明确席位。已绑定席位的右上角在启动／暂停旁提供“断开连接”，各页签均可使用，点击后须确认。断开连接会先暂停和释放控制，再解除绑定，保留槽位配置与私有历史。

执行指令根据独立回执显示下达状态：有接受或执行证据显示“已下达”；明确拒绝显示“未下达”；批次停止后明确跳过的指令显示“未执行”；审计确认整份方案提交前取消且没有提交证据时显示“已取消”。部分回执缺失或结果确实未知时仍显示“提交未确认”，不继承整份方案的成功或取消状态。该展示不改写底层审计与结算记录。

状态接口复用控制台已整理、脱敏并序列化的发布结果；有页面轮询时每 500 毫秒合并更新，多客户端共享同一份结果，停止轮询后停止周期整理。配置、绑定及启停操作完成后立即重新发布。状态查询不重复展开历史命令；性能采样采用独立的批量日志写入，持久性边界见[持久化](persistence.md#控制器私库)。

## 显式配置

bot 后台与指挥官的 Codex 调用使用 `codex app-server` 的持久分页 thread，宿主按服务器 origin、房间和玩家席位隔离身份，再按职责、稳定任务身份、模型、思考档位、服务档位及固定规则区分会话。后台通过不入模的 `providerSessionScope` 提供职责与任务：外交使用具体会话身份，战略和指令转译使用原始任务身份，超限拆分及供应商重试保持原身份；动态 tick、调用编号、尝试次数与 Schema 哈希不参与任务分组。相同名称的不同职责任务仍分别隔离，固定规则改变继续建立新的 thread。未提供任务分组的调用保留 bot 内原有复用边界。每个适配器最多保留 64 个可复用 thread 身份，超出时归档最久未用的空闲 thread。每次调用启动一个短生命周期原生进程，在同一 thread 恢复完成后退出；控制器重启重新建立会话，不从未知旧历史自动续接。

调用开始时确认模型历史为空，结束时确认只有当前一轮，再通过 `thread/revert` 撤回该轮，并分页查询确认历史恢复为空，才返回模型结果。模型历史在调用之间保持零轮，当前世界状态和跨轮认知仍来自程序提供的最新事实与笔记；程序审计、真实命令和回执不受撤回影响。回退失败、历史不符合预期、超时、取消或原生工具请求都会使该 thread 身份失效，不发布本次结果，也不允许下轮继续追加旧历史。运行环境须支持持久分页历史和 `thread/revert`；不支持时明确失败，不静默退化为历史累积。

完整分段输入中连续的 `instructions.*` 固定规则作为 thread 的开发者指令，`brief.*` 动态材料作为当前轮输入，两部分拼接与保存的上下文原文一致。未分段、损坏或固定规则超过 12,000 字符时保留完整的当前轮输入，不猜测分段或截断。缺少宿主隔离身份的独立适配器调用仍使用 `codex exec --ephemeral`；固定空工作目录及工作目录外的独立 Schema 临时文件避免并发覆盖，临时文件在调用结束后清理。

Codex 生成侧使用原响应契约的严格 Schema 投影：每个对象声明全部必填键，不同动作保持独立的封闭分支。原可选且不接受 null 的字段以传输用 null 表达省略；原可选且接受 null 的字段以 `present/value` 对象区分省略与显式 null，`present: false, value: null` 表达省略，`present: true` 表达显式值。原必填 nullable 字段保留业务 null。返回后依据同一原契约还原，再执行原语义、授权引用和发布校验；零、false 及业务 null 不被删除。保存的响应 Schema 为原契约，调用详情以 `openai-strict/2` 标识生成投影，Schema 指纹对应实际传入 CLI 的投影。

生成侧不发送严格模式不支持的 `uniqueItems`；原契约和外交解析仍拒绝重复或无权限的据点，生成侧投影不能替代内部校验。

后台调用详情保存 Codex 实际报告的 thread ID、会话模式、任务分组 `sessionScope`、是否复用、调用前/完成后/回退后的历史轮数，以及固定规则与 Schema 的 SHA-256。Token 使用本轮 `tokenUsage.last`，不将 thread 的累计用量当成本次用量；独立 exec 则读取 `turn.completed.usage`。缓存计数只使用供应商回报，缺失或无效时为未知，明确报告的零才是零。后台响应结构按职责及服务器合同协议能力固定，运行时权限置于动态正文；开局、提案状态、任务及舰队变化不改变固定规则与生成 Schema。指纹和空历史校验不表示缓存已命中；缓存命中仍受模型、输入、有效期与服务端路由影响，不保证每轮发生，也不要求逐轮增加。

OpenAI 兼容适配器适用于 MiniMax、DeepSeek、OpenRouter 和自定义兼容地址。Chat Completions 每次使用一条 user 消息，Responses 每次使用一个 input 字符串，完整保留当轮 prompt 的原有顺序。`json_object` 与纯文本模式将完整响应 Schema 追加在当轮 prompt 末尾；`json_schema` 模式通过原生结构参数发送 Schema，不在正文重复，不额外拆出 system 消息或 instructions 字段。Gemini 在单条当前 contents 中保留完整 prompt，systemInstruction 仅保留适配器原有的 Schema 使用说明，继续通过 generationConfig 提供原生 Schema。Codex 继续使用既有开发者规则与空历史 thread 机制。

Chat Completions、Responses 和 Gemini 的每次请求均重新构造，只发送一份当前材料，不保存或附加 assistant 消息、旧局势、conversation、previous_response_id 或 continuationToken；调用实例复用和失败都不会给下一轮附加历史。程序笔记和实际回执仍按职责提供，不等于底层模型历史。不同接口的缓存比例须用各自返回的缓存用量测量，不能把固定 Schema 或请求身份当成已命中数量。

MiniMax 官方 Chat Completions 接口使用 `MiniMax-M3.1-Flash` 时，适配器把配置的思考档位传为 `reasoning_effort`，避免供应商在省略参数时使用更深的默认思考。该模型专用参数不发送给其他模型或第三方兼容地址。

兼容接口只有正常终止后才返回模型结果：Chat Completions 要求 `finish_reason: stop`，拒绝缺失标记、截断、过滤、拒绝及工具请求；Responses 要求响应与消息均为 `completed`，且没有错误、未完成原因或工具输出。结束原因、协议和合法的响应身份作为 `completion` 计量证据保存，响应正文按最近 20 次调用窗口保留。供应商返回与语义校验、发布分别记为 `transport`、`publication` 阶段；后台调用通道统一使用 `strategy`，控制台分别显示排队、推理、已返回、已发布、过时和依据失效。已发布不表示游戏指令或战斗已结算。

远程 origin 必须 HTTPS，回环可用 HTTP。不得在配置或命令行填实际令牌。默认凭证是 executor grant；显式 `ownerCredential: true` 时只用于核对 owner 身份并引导独立 executor 授权，记录持久保存在私库。授权撤销或过期后停止，不偷偷签发替代凭证。

`--provider` 默认为 `offline`，表示不配置模型，hybrid 前台使用本地自主规划；不会调用供应商或制造模型 finish 回执。配置模型可使用 `--provider env` 及正确环境供应方，或控制台提供器设置。供应商实现与环境变量见 `application/providers/provider-factory.ts`，配置校验见 `controller/contracts/agent-config.ts`。

原生 Gemini 默认使用运行时环境中的 `HTTPS_PROXY`／`HTTP_PROXY`，不硬编码代理地址；本机使用 7890 时将对应变量设为 `http://127.0.0.1:7890`。Node.js 环境代理初始化要求 24.14+，自动保留 `127.0.0.1`、`localhost`、`::1` 绕过代理，避免本机游戏与控制台请求绕行。模型超时沿用席位配置和调用时限，暂停取消在途请求；不会为了失败重试绕过现有调用队列和退避策略。

无网页的持续运行支持 stdin JSON Lines：`status`、`start`、`pause`、`run-one`、`shutdown`。`run-one` 在暂停席位执行完整一轮，可能含多次调用，然后暂停。

Schema 的生成侧约束、当前兼容性限制和真实模型验收要求见 [Gemini 结构化输出规范](gemini-schema.md)。

## 调度

本机与公网控制台使用 `state.sync/1` 独立同步通道：服务器在变化响应中返回同一版本的完整授权局势，本地安装后唤醒前台。正常前台读取使用本地已同步快照，不再次查询事件、分页下载或等待快照完成确认；实时模式使用同一路径。同步采用完整授权视图替换，不维护逐字段增量合并器。首次连接、执行前的显式权限检查、已接受写入后的恢复及事实缺口仍可访问服务器；本地快照只代表最近成功同步的状态，实际提交仍由服务器校验当前事实。 网络请求计时仅追加审计记录，不读取或写回决策、指令和笔记；诊断行动明细按稳定操作身份索引查询。

分层协同在服务器协商支持 `actions.batch/1` 时按整批约束校验后提交，服务器顺序执行并返回逐项回执和一份最终授权快照；调试断点及不支持该能力的服务器保留逐项执行。批次传输失败按原身份查账，快照失败不抹去已提交的回执。协议边界见 [Player Protocol 2.0](../../protocol/player/v2/README.md)。

程序化与分层协同共用进程级预测线程池；默认使用可用逻辑处理器数减一、最多八个线程，至少一个。`AI_FORECAST_CONCURRENCY` 可显式设置为 1–16，与模型并发分别配置。待运行预测按房间/玩家轮转，同席位先进先出；各席位不会分别创建一套预测池。完整观察按需装载到线程，取消中的槽位等待确认后复用。`botForecastPoolStats()` 提供任务数、缓存命中、线程创建、上下文装载，以及累计排队、计算、准备与传输耗时；并行任务的累计耗时不能当作实际墙钟时长。缓存与隔离边界见[授权预测](prediction.md#缓存与展示)。

单席位仅一个在途战术决策，自动运行每个 tick 最多启动一轮前台判断；已开始的轮次可以跨 tick 继续搜索、执行与查账。准入依据持久化的 `started.tick` 和 `foreground-closed.tick`，重启或暂停后恢复不会重开同一个 tick。上报就绪前先持久关闭该 tick，包括没有触发决策的空闲 tick；回执丢失不重新开放决策。同 tick 后到的提醒、状态变化、后台结果和恢复任务合并保留到下一 tick，继续按原触发原因及事件合并窗口判断。新 tick 只重新开放准入名额，不产生额外策略复查信号；没有实际触发就继续观察并报告就绪。显式“运行一轮”可绕过这一自动准入限制。轮询、搜索步骤和回执查账不计作新轮次。

事件等待通道区分新 tick、控制权变化与后台来信。同 tick 前台已完成且就绪已确认后，普通状态变化只更新本地同步快照，下一 tick 交给前台统一处理，不再重复前台观察、收集和就绪上报。后台来信、指挥官材料和本地发布通过后台分支摄取与发送外交结果，不收集前台触发、不再次上报就绪；后台发布保留为下一轮原因。新 tick 从本地同步快照整理完整材料并判断是否需要行动，无实际触发也可完成当前 tick。事件在处理期间到达时保留待处理标记，不丢失新 tick 或后台发布。定时调度只承担续租、指挥官处理、合并等待、首次接入和未决操作恢复，正常事件通道下不重复读取空闲席位。前台计算期间仍可向后台递交资料，不另开前台轮次。本机自动推进、公网对局定时调度及事件唤醒均使用模式规定的事件合并窗口，分层协同为 1 秒。

就绪表示指定 tick 的前台工作及实际回执已完成，不表示已消费本 tick 后续所有事件。每个控制会话、tick 只需确认一次；同 tick 的消息、状态及指挥官版本变化不撤销完成状态，也不提升行动提交的授权版本。跨 tick、控制权释放或失效会使就绪失效，未决游戏写入仍阻塞推进。实际游戏命令继续独立校验当前权限、指挥官版本、行动依据和资源；显式运行一轮会先撤销就绪。

自动决策入场不发送撤销就绪请求：上一 tick 的就绪已失效，当前 tick 一旦关闭就不再自动重开。租约续期独立于前台轮询；原租约仍有效时继续正常调度，已过期的席位只等待本席位续期结果，不阻塞其他席位。权限失效、暂停和恢复查账仍按原有边界处理。

事件同步通道的只读传输中断单独记入运行日志，由现有定时调度重新建立该通道，不撤销仍有效的租约、取消已固定材料的前台轮次或清空游标。SDK 为整个 HTTP 交换设置硬期限，涵盖响应头与正文；底层取消或正文清理不结束也不能无限挂住调用，迟到响应不得更新协议状态。HTTP 头已返回但正文读取超时仍属于传输失败；完整正文的 JSON、UTF-8 或容量校验失败继续停止运行，权限失效与未确认写入继续执行原有控制权和回执恢复流程。

后台独立读取并消费消息后，共享消费游标可能领先固定前台快照。只有本实例已通过授权后台读取证明的消息前缀允许领先；前台返回自身快照的集合边界，不回退共享消费游标、不重放已消费消息，也不为追赶后台强制刷新。无读取依据的越界游标仍拒绝。独立事实快照早于持久确认基线时，只验证并保留该快照自身的事实，不补入较新事实或倒退确认基线；房间、玩家、序列及内容校验继续有效。

分层协同每席位最多一个受控后台模型任务，并与本席位指挥官讨论共用一个模型调用槽位。外交来信由该模式后台外交 AI 持久接收、解释和生成回复建议，不因来信额外启动前台。前台在允许的轮次依据当前有效约束处理后台建议，实际提交仍通过统一执行器。

未设置 `AI_MODEL_CONCURRENCY` 时，全局总容量固定为八：所有席位共享最多七路自动模型调用，另预留一个讨论通道，不随启用席位数量增加。每个 bot 同时最多占用一个模型调用槽位，后台任务和指挥官讨论共用这一席位限制；不同 bot 可以并行，超过全局容量的任务排队；程序席位不占模型名额。显式设置 `AI_MODEL_CONCURRENCY` 可覆盖为 1–32 的固定总容量；大于一时预留一个讨论通道，例如设置为九才允许八路自动调用。此处是本机调度配置范围，不是供应商承诺的并发限额。容量下降不终止已开始调用，只限制后续准入；有等待时按席位轮转，同席位保持先入先出。

分层协同后台不使用从入队开始的总超时，模型供应商计时从准入后开始，普通思考默认两分钟、高思考默认五分钟，显式供应商超时配置优先；暂停会取消排队和在途任务。发出前复核确认指令及任务版本，过时任务不发送。无调用总量或 Token 总量配额，但保留上下文和时间保护。状态接口返回当前模型队列容量、活动数和等待数。

实际收到 HTTP 429 后，共享队列首次暂停新派发30秒，并将自动调用容量减半，至少保留一个自动通道；在途调用继续收尾。同一批在途调用的限流共享一档等待，冷却结束后再次被拒绝则逐档延长为60、120、240秒，最多300秒。冷却后先放行一个恢复探测请求，讨论与自动调用共同遵守这一限制；成功后恢复当前容量，每两次成功调用重置连续限流计数并增加一个容量位置，逐步恢复到配置容量。该反馈避免各席位分别重试形成请求洪峰。Codex CLI 明确记录 Responses 请求 HTTP 429 时提前结束内部静默重试，并记录为限流而非等待到供应商超时；单独的模型目录刷新警告不触发此处理。状态接口的限流字段给出当前容量上限与下次准入时点。

发送前重新核对授权观察、重要事件、确认指令和私有状态依据。请求在途不改上下文；返回后写入仍按当前权限、版本和资源校验。恢复策略见[执行守卫](ai-execution-guards.md)。


## 暂停、重启与存储

已绑定的 bot 可以在房间集结时启动，并持续显示等待开局；集结等待不占用获取控制权的 35 秒期限。房间准备好后才开始身份校验与租约获取，已有执行器仍续租时不会强行接管。每次大厅读取独立限时 15 秒，网络中断或超时沿用自动重连退避；身份失效、席位不符或房间取消停止启动。等待期间暂停会取消请求和轮询，不会在房主随后开局时继续启动。

暂停先禁止新写入，等待在途操作与持久回执收尾并释放租约。服务器已经接受的预约不会因此撤销。普通启动默认暂停，不自动重放历史指令。服务器明确返回 `LEASE_LOST` 时，客户端丢弃旧会话与租约；下一次恢复重新握手、核验身份并查账，不沿用失效会话或自动重发未决写入。

`scripts/dev-agent.mjs` 默认只热更新控制台前端，后端源码变化不会自动重启。活跃测试局的后端更新使用联动存档及重启流程。隔离开发时可显式加 `--backend-reload` 启用后端热更新：先完成构建，再记录当时正在运行的席位，等待操作收尾并正常关闭旧控制器。新进程就绪、绑定恢复且服务器、房间及玩家身份一致后，自动恢复这些席位；原来暂停或未绑定的席位不启动，身份变化或已结束的席位不恢复。运行意图只通过监督进程的内存交接，不作为普通启动的自动运行配置。构建失败保留旧进程运行；恢复失败明确记录席位，不声称恢复成功。纯前端更新不改变席位运行状态。

私库按 server origin、roomId、lobbySeat 和实战标记隔离，每库有单进程锁。锁残留时确认原进程已退出，再仅删除对应失效锁；不删数据库、WAL 或 SHM。具体备份和一致性边界见[持久化](persistence.md)。

游戏与控制器后端协调重启，流程见[本机联动存档](linked-checkpoints.md)。开发监督器的单边热重启不是完整联动恢复。

## 机械保活与诊断

有效游戏行动由服务器自动记录签到，普通 AI 不单独发送签到或设置签到提醒。默认不启用机械保活。明确配置的 `mechanicalKeepalive: true` 还需 `roomMaintenancePolicy` 精确匹配房间并允许维护。维护仅按权威活跃字段执行签到/取消警告，不能复活出局席位、代替战略决策或绕过未知写入。

统计区分模型决策、讨论、指令整理、程序化搜索和工具调用。Token 只按供应方实际回报累计，缺失用量是未知；模型调用失败不等于游戏命令失败。检查当前运行需同时看真实进程、有效租约、回执、实际完成记录和自然推进，不能仅凭 thinking、调用数或瞬时 owned 标记判断。

私库审计中的 `execution-tool-timing` 按工具记录权限检查、执行准备、工具执行、结果处理、结束时权限复核和本地提交耗时；`protocol-request-timing` 记录协议请求的方法、不含查询参数的路径、开始时间、完整响应读取与解析耗时及状态码，不记录凭据或正文。工具阶段按顺序切分；并发请求的耗时可能重叠，不能将请求耗时之和当作整轮墙钟耗时。请求检测点回调失败不改变请求结果。

后台观察、外交和指挥官工作与程序前台分别调度，不共用前台观察锁、取消控制器或操作上下文。后台只读失败单独记录，不作为普通前台运行失败；权限失效及持久化错误仍遵守各自安全边界。局势、聊天、通知以及独立的活动和人工事实补读并行，依赖同一游标的分页和实际操作提交顺序保留。事件合并窗口包含本次观察与查账所花的时间，读取完成时已达到窗口即可在同次轮询开始决策。游戏操作执行前核验远端权限；finish 收尾只核对本地版本和 CAS，不为保存私有结果重读远端身份、控制权或完整观察。其他私有编辑入口执行前及本地提交前仍分别核验权限；单次核验中的指挥官要求和人工操作版本共用一份已核验的授权资料，不在两个核验边界之间缓存复核结果。指挥官线程仍核对房间和实际玩家身份，版本变化继续拒绝旧操作，本地状态提交保留 CAS。

本机隔离测试可使用 `node scripts/report-bot-cycle.mjs --directory <运行目录> --game-port 4310` 生成周期数据报表。目录须包含当前 `controller-bindings.json` 及私库。首次从各私库最近启动标记后的共同起始 tick 统计，时间取首个模型入队记录，不能混用旧启动文件中的更早基线；没有对应日志或席位起始 tick 不一致时拒绝自动生成首报。之后以保存的日志游标和游戏 tick 差分；切换房间或回退存档时须保留旧报表并建立独立统计段。生成器只读运行状态，不推进或暂停游戏；JSON、HTML 和游标保存在运行目录的 `cycle-reports/`。

报表区分决策轮次、新完整搜索、定向复核、条件仿真请求和实际派发的模型请求；缓存搜索复用、轮询及尚未派发的排队请求不混入搜索或实际模型请求数。搜索按所属决策轮的触发记录归因，模型请求按其已记录材料和调度事件归因，补查与重试单列，无法关联时标记未知。一次操作可有多个原因：覆盖率表示涉及该原因的操作比例，均摊占比将一次操作在其多个原因间等分。各私库独立采样，不能把报表当作暂停后的全局一致检查点。

## 源码扩展入口

官方构建默认 hybrid，自定义构建通过封闭注册目录选择完整 AI 实现；只在暂停且未决操作已经核对后切换。公共入口、组件注入、模型结果和运行示例见[AI 源码扩展](ai-extensions.md)。指挥官工作线程属于共用运行基础，hybrid 只提供战略材料和提示词。
