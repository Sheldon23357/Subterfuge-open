# 授权预测与进攻分析

## 输入边界

`packages/prediction` 只接收玩家有权取得的观察和明确提交的假设，不读取游戏服务器、完整导出、隐藏兵力、随机种子或分配游标。浏览器和控制器共用规则，SDK 传输层不依赖引擎。

公开兵力总数不等于知道其分布；未知据点、舰队与生产相位保留 unknown。观察中的 retained/公开字段不能被扩大成权威全图。不能先模拟完整隐藏世界再过滤。

预测仅在给定起点、已知预约与显式假设下成立，不预知敌人新命令。实际结算由服务器的授权事实和回执确认。

## 计算接口

| 能力 | 调用方 | 作用 |
| --- | --- | --- |
| 已知状态预测 | 网页/控制器 | 给定终点的条件分支 |
| 路线/出兵预览 | 网页/控制器 | 单条路线、合法准备时间和条件结果 |
| 舰队预计抵达 | 当前选中单位/控制器 | 当前可知路线与时点估算 |
| attackRoutes / 进攻初筛 | 控制器 | 可达来源、目标与初步兵力建议 |
| forecast / compare | 模型工具及程序化规划 | 联合草案、hold 基线与备选比较 |
| decisionSupport | 模型只读工具 | 显式范围的有限搜索 |

这些计算在客户端完成，不对应远程计算 HTTP 路由。真实历史通过 owner 历史接口读取，实际活动通过 activity 分页读取，二者不能由预测替代。

## 资源、路径与时间

同套草案按联合分支执行，处理已有预约、兵力、准备时间、来源留兵和调度锁。未来资源必须在实际支付时点可用，不能用最终收益倒付费用。未预约计划不锁兵，不同备选方案的共享兵力不能相加。

路径谓词区分全程持有、终点持有、期间攻占、无失矿和终点最低驻军，结果为满足/不满足/未知并保留最早反例。终点夺回不能抹去过程失矿。资源和路径检查来自同一分支，提前终局、覆盖截断和未知明确报告。

预测终点、实际抵达可以为小数世界日；自动预约与显式出发边界须遵守[世界时间](world-day-time.md)。`arrivalTick` 不能冒充精确步内 ETA。

## 比较与搜索

compare 使用共同终点并自动加入 hold 基线，默认只展开共同相关目标、来源和舰队；各方案摘要、过程风险、终局及覆盖仍保留。最多四套方案，每套最多八条草案，窗口不超过 144 世界日。

decisionSupport 支持 allocate、force、timing、sync、support。默认 32 次模拟、2,500 毫秒，上限 128 次、30,000 毫秒；queries 的独立子项共享整批预算。同步计算在分支之间检查预算，不能把协作式预算宣传为单次硬抢占。

有限搜索报告覆盖与截断。资源分配可行不代表战斗胜利，未搜索的组合不代表失败，启发式排序和评分不是胜率或全局最优。

## 缓存与展示

缓存依赖实际观察、规则、来源/目标、舰队、预约、时间及参数；即使复用静态路线，也须重新绑定当前依据。版本冲突不能通过改标签复用旧结论。

同一完整授权观察可以通过 `prepareKnownPrediction` 预构建规则世界，再为各套草案创建独立分支。预构建只复用观察重建，不共享分支的可变状态、命令、路径记录或检查点；后续观察或步内时间变化需要新的依据。该方式与普通预测使用相同引擎和校验，不缩短推演窗口或放宽未知边界。

路线估算使用普通舰队速度与准备时间，仅向外返回标量。纯运动学计算按完整坐标、地图尺寸、时间、窗口及准备时间复用，最多保存 8,192 项；不缓存归属、资源、可见性或战斗结论。

控制器预测线程按完整观察内容指纹装载上下文，包含房间、玩家、版本和步内时间；请求缓存还区分全部草案、假设、谓词和终点。每线程保留最多四份预构建观察、最多 32 个且合计不超过 4 MiB（按 UTF-8 JSON 大小计）的结果，旧上下文按最近使用情况淘汰。取消通过共享标志在推进块之间检查，取消结果不进入缓存；线程确认结束后再处理下一任务。线程配置与公平调度见[bot 运行说明](ai-runtime.md#调度)。

浏览器预测与历史重建在 Worker 内运行，取消过时工作并有界缓存；历史按当时玩家迷雾投影。列分组或表格压缩只改变展示，不删除方向、精确时间、身份关联、未知或实际结果。
