# 地图生成

## 候选与初始配置

当前新局支持 2–10 人，请求种子为整数。参考生成器保留固定规则的随机数、Float32 顺序、环绕距离及共享建筑类型序列，本地新局从请求种子起检查连续 500 个候选，保留候选坐标、归属与玩家初始建筑，中立建筑按目标比例分配。

每人目标十个据点的地图总量；初始分配五个据点，一处普通出生据点零兵，另外四处各 40 兵，中立点零兵。同局各玩家初始配置统一为两电厂三工厂或三电厂两工厂，全图初始电厂目标比例为 45%，电厂数取 `floor(据点总数 × 45 / 100 + 0.5)`。偶数人数精确达到45%，例如8人局36座电厂/80据点；奇数人数按最近整数取值，例如3人局14座/30据点。

地图面积随人数变化，点间最小环绕距离、出生点和建筑均衡按候选生成规则校验。不能用屏幕直线距离替代环面距离。

## 模式

`POST /api/new` 的 mapMode 为 quantity-priority 或 original，默认数量优先。两者使用相同候选布局、建筑分配与额外产品筛选。建筑分配仅调整中立点：增加电厂时优先补足电厂相对少的潜在领地，减少时优先选择相对多的领地，同档按种子确定顺序。类型变化的中立点生产进度从零开始；护盾、兵力及出生配置不变。大厅提前开始而重建地图时，也使用同一建筑分配规则，不更换已指定的候选种子。

数量优先依次比较：

1. 潜在领地数量最大差最小。
2. 升序领地数量分布，先提高最少方，再比较下一方。
3. 数量分布相同后，比较边境、普通出生据点到敌方、最近中立点的相对几何差异。
4. 全部相同保留最早候选种子。

原版模式沿用原候选领地评分。静态指标不保证实战胜率或每种几何指标都改善。

## 保存与实现

建筑分配标识为 `generator-45-v1`，独立于领地选择算法标识保存；参考生成器默认30%–60%及原始建筑序列保持原样。普通出生据点使用startingOrigins记录，不创建特殊单位。保存算法标识、人数、请求/最终种子、领地评分及模式需要的选择摘要。推进和恢复不重新选图，摘要描述初始地图。算法改变需使用明确版本标识，不能用相同标识悄悄替换选择规则。

运行生成器位于 `packages/engine/src/ordinary-map.generated.ts` 及公开地图模块，只创建普通据点；固定参考保留在 `original-map.generated.ts`。`scripts/extract-map.mjs` 按 AST 白名单提取原始算法，再由 `scripts/ordinary-map-adapter.mjs` 生成普通玩法适配器，`--check` 同时核对两者。几何、建筑分配和初始兵力保持一致，不创建专家或专家缓存。运行游戏使用提交的规则代码，不依赖本机 APK。
